# Два GPU-эксперимента калибровки

- `xgboost_oof_smoothed_dual.ipynb`: сглаженная скалярная калибровка по свежим OOF-ошибкам.
- `xgboost_oof_meta_dual.ipynb`: те же скалярные варианты плюс XGBoost-метамодель коэффициента.

Подключить `case_rwb`, включить GPU в Kaggle и выполнить Run All. Обучение запускает пользователь. Ноутбуки самодостаточные; параметры восьми горизонтов встроены из `xgb_tuning/best_params`. Проверяются общая модель и8 кластеров; `MODEL_CLUSTERS=(8,)` сокращает число моделей. Три недели OOF, неделя выбора, test и полный refit требуют больше времени, чем прежние два блока val.

Обучение и предсказание базовых и метамоделей работают на CUDA без CPU fallback. Для базы CuPy-батчи подаются в `QuantileDMatrix`; сжатый обучающий датасет хранится в VRAM. Метадатасет целиком передаётся через CuPy. Не требуется держать весь исходный parquet на GPU. Чтение parquet, подготовка rich-признаков, KMeans, pandas-таблицы и запись файлов выполняются на CPU. Используется GPU0, второй T4 автоматически не задействуется. GPU-ускорение обучения не устраняет стоимость подготовки признаков. Нужна CUDA-сборка XGBoost с GPU DataIter/QuantileDMatrix и CuPy; автоматической установки зависимостей нет.

Val28дней: первые21 дают три недельных OOF-блока с обучением только до начала соответствующей недели. Последние7дней выбирают вариант модели и калибровку по WAPE+|Relative Bias|. Test14дней остаётся прежним и не участвует в выборе. Перед оценкой test калибратор переобучается на OOF val28 и замораживается. На test не обновляется по прошлым меткам test. Период уже изучался в проекте и не является новым слепым holdout.

Скалярные правила: raw, fixed1.05, global, свежие3/7/14дней, смеси long/recent с alpha.25/.5/.75. Метамодель: коэффициент y/raw, веса raw/mean(raw), GPU XGBoost squarederror. Упрощённые входы —12 признаков: нормированный/log raw, log масштаба маршрута, текущий таргет, средние за2/24часа, изменение зачас, статусы1–3 и категориальные горизонт/кластер. ID маршрута и полный rich-набор в метамодель не входят. Базовые модели сохраняют rich-признаки. Признаки не читают текущий y. Для малых raw применяется глобальный fallback, итоговый коэффициент ограничен0.8…1.25. Три простые конфигурации метамодели: depth1/50деревьев, depth1/100, depth2/150; learning_rate0.03, reg_lambda100, min_child_weight100. Эти конфигурации и сила усадки к глобальному.5/1 сравниваются на val со скалярными baseline. Если baseline лучше, он используется для сабмитов; метамодель не навязывается.

Два основных сабмита:

1. `submission_train_val.csv`: базы и статистики обучены до `TEST_START`, калибратор — на OOF val. Это диагностическое исключение из стандартного full-history refit по прямому запросу пользователя.
2. `submission_full.csv`: базы полностью переобучены на всей размеченной истории, калибратор — на всех доступных OOF val+бывший test, без повторного выбора правила по test.

Также сохраняются raw-версии обоих. Все файлы находятся в `/kaggle/working/cluster_experiment_…/`. В обоих режимах признаки для конкурсных дат используют всю уже известную на cutoff историю. Независимая от полного refit оценка test получена до переобучения. Таблица `independent_metrics.csv` содержит raw/calibrated test и отдельно in-sample оценку калибратора на OOF val; базовые train/test всех fit находятся в `base_*_metrics_by_horizon.csv` и `fit_report_*.csv`. Эти разные значения train явно разделены.

Архив в самом конце содержит модели каждого OOF-этапа, train+val и full, метамодели, статистики, источники параметров, протокол/выбор, прогнозы OOF/test/future с множителями, таблицы метрик и все четыре сабмита. `calibration_frozen.json` фиксируется до test, `evaluation_complete.json` — до full refit. Модели base checkpoint имеют проверку границы fit и hash кода. ZIP появляется только после успешного завершения, промежуточные файлы доступны и при сбое.

Генератор: `scripts/build_dual_calibration_notebooks.py`. Проверки: `scripts/check_dual_calibration_notebooks.py`, `scripts/check_xgb_gpu_shrinkage.py`, `scripts/check_rich_gpu_features.py`. Проверены синтетический полный сценарий, отсутствие чтения test при выборе/предсказании, причинность признаков, CUDA-контракт, два режима обучения, порядок id и содержимое ZIP. Настоящий запуск на GPU при подготовке не выполнялся; скорость и достаточность VRAM должны подтвердиться в Kaggle.
