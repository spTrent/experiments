# Стекинг для 1000 маршрутов и восьми горизонтов

Соберём **34 прогнозных признака**: 30 прогнозов глобальных моделей, три прогноза маршрутных Ridge и один сезонный `profile28`. На одной и той же таблице сравним **Weighted Average, CatBoostRegressor и GatingNetwork**. Победителя выберем по последовательным временным окнам до локального test.

## 1. Базовые модели и три режима train

| Режим | Первые 25% train | Оставшиеся 75% train |
|---|---|---|
| `five_starts` | Пять стартов | Пять стартов |
| `mixed_starts` | Пять стартов | Все получасы |
| `recent_all` | Пропускаем | Все получасы |

- Пять стартов — **09:30, 10:00, 10:30, 11:00 и 11:30**. Четверть считаем по хронологически упорядоченным датам доступного train **отдельно в каждом фолде**. Первые `floor(N / 4)` дат составляют ранний период. Фильтр меняет обучающие строки. Более ранние наблюдения остаются доступными для вычисления лагов и сезонности на момент прогноза.
- Во всех трёх режимах обучаем RF, LightGBM, CatBoost, XGBoost и глобальную Ridge, каждый в `direct` и `residual`. Берём настройки соответствующего горизонта из `model_params`. Проверены все **80 конфигураций**: параметры и оценки совпадают с лучшими завершёнными trials, число деревьев бустингов совпадает с медианой по фолдам. В частности, 5 и 7 деревьев у XGBoost residual на h6 и h7 подтверждены логами. Для двух новых режимов переносим настройки без повторного подбора, чтобы оценить именно эффект состава train.
- **8000 маршрутных Ridge дают одну колонку на режим.** Для каждой строки прогноз выдаёт одна модель соответствующей пары `(route_id, horizon)`. Сохраняем признаки, индивидуальную стандартизацию и пакетный GPU-решатель существующего ноутбука. Исходные `alpha` выбирались на **4–17 октября**, поэтому для сентябрьско-октябрьского OOF они содержат информацию из будущего. Для каждого из трёх режимов заново выбираем `alpha` каждой пары по 30 кандидатам из исходного диапазона на трёх недельных tuning-окнах, заканчивающихся **19 сентября**. Используем среднюю конкурсную метрику по окнам и исходный резервный критерий MAE при нулевом объёме. Затем фиксируем все `alpha`. [Протокол маршрутных Ridge](../docs/ridge_by_route_horizon.md)
- `profile28` считаем один раз на строку. У residual-моделей возвращаем сезонный уровень до записи прогноза. Все 34 колонки содержат прогноз в исходных единицах цели.

## 2. OOF и независимый test

| Этап | Даты 2025 года | Что делаем |
|---|---|---|
| Подбор баз | По 19 сентября | Фиксируем параметры глобальных моделей и `alpha` маршрутных Ridge |
| OOF-1 | 20–26 сентября | Обучаем базы на прошлом, прогнозируем неделю |
| OOF-2 | 27 сентября – 3 октября | Расширяем train, повторяем |
| OOF-3 | 4–10 октября | Расширяем train, повторяем |
| OOF-4 | 11–17 октября | Расширяем train, повторяем |
| Локальный test | 18–31 октября | Один раз оцениваем заранее выбранную конфигурацию |

Для каждой OOF-недели используем только train-строки, у которых **время целевой метки строго раньше начала недели**. Это важно на длинных горизонтах: старт может попасть в train, хотя его метка уже относится к следующему периоду. Корреляционные лаги и преобразования обучаем заново в пределах истории фолда. Каждую неделю прогнозируем только старты **10:30**. Метамодель получает исключительно прогнозы баз на отложенных строках.

Ожидаемый результат — **224 000 уникальных строк OOF**: 28 дат × 1000 маршрутов × 8 горизонтов. Ключ строки — `(route_id, cutoff, horizon)`. Сохраняем также время метки, факт, номер фолда и границу обучения. После каждого fit выводим таблицу `train / отложенная неделя` с WAPE, знаковым Relative Bias и `WAPE + |Relative Bias|`. На этапе независимой оценки выводим `train / test`. [Исходный временной протокол](../docs/model_experiments.md)

## 3. Четыре параллельных запуска Kaggle

Один параметризованный ноутбук для баз и один ноутбук для сборки, сравнения и финального прогноза. Обучение запускаешь ты в Kaggle.

| Запуск | Горизонты | Объём работы |
|---|---|---|
| 1 | h1, h8 | Все модели, три режима, четыре OOF-недели |
| 2 | h2, h7 | То же |
| 3 | h3, h6 | То же |
| 4 | h4, h5 | То же |

- Каждый запуск пишет прогнозы по завершении задачи `горизонт × фолд × режим × модель`. Для маршрутных Ridge сохраняем прогресс по пакетам маршрутов. При возобновлении проверяем хеши входов, параметров и версию кода, затем выполняем только незавершённые задачи.
- Признаки готовим блоками для одного горизонта за раз. Для `mixed_starts` и `recent_all` нужны реальные получасовые строки. Кеш, рассчитанный только для пяти стартов, не покрывает эти режимы.
- Перед длинным запуском проверяем один фолд на коротком горизонте: все три маски train, совпадение пятистартового режима с исходным пайплайном, пиковую RAM/VRAM для самого большого режима, сохранение и возобновление. Это существенная проверка: только OOF требует **960 обучений глобальных моделей и 96 000 fit маршрутных Ridge** до учёта подбора `alpha`. Завершение каждого запуска за одну сессию Kaggle заранее не предполагаем.
- Сборщик принимает четыре результата и проверяет полноту ключей, совпадение фактов и сезонного прогноза, конечность всех 34 колонок и отсутствие пересечений train с прогнозируемой неделей. Пропущенный файл выдаёт конкретную задачу для дозапуска.

## 4. Как выбираем стекинг

Все кандидаты проходят три одинаковые проверки: `OOF-1 → OOF-2`, `OOF-1+2 → OOF-3`, `OOF-1+2+3 → OOF-4`. Основной критерий — среднее из трёх недельных значений конкурсной метрики. Дополнительно показываем WAPE и знаковый bias каждой недели, общую метрику по всем проверочным строкам и разбивку по горизонтам. Для ориентира включаем простое среднее и одиночную базу, выбранную только на предшествующих данных.

| Мета-модель | Первая реализация |
|---|---|
| **Weighted Average** | Один вектор из 34 неотрицательных весов с суммой 1. Подбираем веса непосредственно по метрике конкурса на train-части метамодели через линейное программирование. |
| **CatBoostRegressor** | Один общий регрессор предсказывает поправку к среднему 34 прогнозов. Признаки — сами прогнозы, их разброс, горизонт и день недели. Сравниваем глубины 3 и 5, число деревьев 100 и 300, `learning_rate=0.03`. |
| **GatingNetwork** | Те же входы, стандартизация по meta-train, один скрытый слой на 16 нейронов и 34 веса через `softmax`. Начальные веса равные. Обучаем по суммарной конкурсной метрике train-окна с `Adam`, `lr=0.001`, фиксированным seed, сравниваем 50 и 150 эпох. Компонент bias считаем по всему окну. |

Чтобы измерить пользу **именно 8000 Ridge**, для каждого кандидата повторяем сравнение с тремя маршрутными колонками и без них. Повторного обучения баз для этого не требуется. Выбираем состав и настройки по лучшему среднему недельному результату; при точном равенстве предпочитаем меньше колонок, затем Weighted Average. Публикуем все три недельных результата, чтобы был виден выигрыш, зависящий от одной недели.

## 5. Финальная оценка и сабмит

1. Фиксируем победителя до просмотра результатов стекинга на test. Обучаем его на четырёх OOF-неделях. Входящие в него базы обучаем на допустимых строках до **18 октября**, применяя их режимы, и прогнозируем 14 тестовых дней с ежедневным обновлением доступных признаков. В отчёте явно указываем: **независимая оценка test получена до переобучения на всей истории**. Этот период уже изучался в проекте, поэтому отдельно сохраняем результаты трёх предтестовых проверок.
2. Для финального обучения метамодели добавляем две октябрьские недели с новыми последовательными OOF-прогнозами. Первый недельный блок можно взять из только что сохранённых test-прогнозов. Для второго базы переобучаем на истории до 25 октября. Выбранные настройки остаются зафиксированными.
3. Перед сабмитом переобучаем все базы выбранного ансамбля на всей доступной размеченной истории с соответствующим режимом отбора строк. Собираем **8000 прогнозов** на 1 ноября, проверяем совпадение исходных `id`, порядок, конечность и неотрицательность. Сохраняем `submission.csv`, OOF-таблицу, метрики и конфигурацию победителя.
