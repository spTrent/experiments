# Прогноз объёма отправлений по маршрутам RWB

Решение задачи прогнозирования `target_1h` для 1 000 маршрутов на восемь получасовых горизонтов. В 10:30 формируем прогнозы с 11:00 до 14:30. Итоговый файл содержит 8 000 строк с колонками `id,y_pred`.

**Лучший результат команды на закрытом тесте составляет 0,326.** Его получил запуск **Session6**, который объединяет прогноз прежнего решения 0,328 и маршрутное распределение LightGBM. Готовый CSV, сохранённые модели, код восстановления и локальные прогнозы собраны в [best](best/).

## Лучшее решение, Session6

Решение разделяет прогноз суммарного объёма и его распределение между маршрутами.

1. Берём прогноз решения 0,328 на основе CatBoost, сезонного профиля и обучаемых поправок. Его сумма по всем маршрутам задаёт объём каждого горизонта.
2. Восемь моделей LightGBM, по одной на горизонт, прогнозируют нормированный уровень маршрута. Для обучения используются пять утренних стартов и расширенный набор признаков. Прогнозы LightGBM нормируем к суммарному объёму первого компонента.
3. Смешиваем два распределения между маршрутами с весом LightGBM **0,4997259**. Общий объём каждого горизонта сохраняется, а доли отдельных маршрутов меняются. Вес выбран на историческом периоде 11-17 октября 2025 года.

| Оценка Session6 | Значение |
|---|---:|
| Закрытый тест соревнования | **0,326** |
| WAPE на локальном test | 0,317827 |
| Модуль Relative Bias на локальном test | 0,001364 |
| WAPE + модуль Relative Bias на локальном test | **0,319190** |
| Средняя дневная метрика на локальном test | 0,336039 |

На локальном test изменение распределения снизило WAPE с 0,320090 до 0,317827 и суммарную метрику с 0,321454 до 0,319190 относительно решения 0,328. Модуль общего смещения сохранился. Метрики рассчитаны на 112 000 прогнозах за 18-31 октября, старт каждого дня в 10:30. Результат 0,326 на закрытом тесте сообщён командой. [Конфигурация](best/bundle/config.json), [локальные метрики](best/bundle/metrics.csv), [готовый сабмит](best/submission_session6.csv).

Комплект Session6 восстанавливает прогноз из сохранённых моделей и исходного CSV решения 0,328. В метаданных указано `source_models_refitted=false`, в этом запуске исходные модели повторно не обучались. Сохранённая локальная оценка получена до финального переобучения и относится к архивной конфигурации. Исторический test уже использовался в нескольких экспериментах, что ограничивает независимость последующих сравнений на тех же датах. Для следующего сабмита требуется отдельный этап переобучения моделей по всей доступной размеченной истории. [Манифест запуска](best/bundle/manifest.json).

Предыдущий результат команды **0,330 на Public** получен в `stepa330`. Там используются отдельный CatBoost на каждый горизонт, смесь 70% CatBoost и 30% сезонного профиля на h2-h8 и аддитивная поправка на объём. Эта конфигурация сохранена как контроль для экспериментов. [Ноутбук stepa330](notebooks/stepa/stepa330.ipynb).

## Данные и проверка качества

Размеченная история содержит 4 630 000 строк с 28 июля по 1 ноября 2025 года, 10:30. Для каждого маршрута доступны временная метка, цель `target_1h` и шесть статусов. Конкурсный прогноз строится на 1 ноября 2025 года. Исходные файлы и описание задачи доступны в [data](data/) и [материалах соревнования](docs/competition/).

Метрика соревнования складывается из WAPE и модуля Relative Bias. WAPE равен сумме абсолютных ошибок, делённой на суммарный фактический объём. Relative Bias равен сумме ошибок со знаком, делённой на тот же объём. Поэтому при выборе решения учитываем одновременно точность маршрутных прогнозов и смещение общего объёма. Меньшее значение метрики соответствует лучшему результату.

Базовое хронологическое разбиение проекта показано ниже. В Session6 период 11-17 октября использован для выбора веса распределений, а 18-31 октября для локальной оценки.

| Период | Даты 2025 года | Назначение |
|---|---|---|
| Train | 28 июля - 3 октября | Обучение базовых моделей с учётом выбранного окна истории. |
| Подбор | 4 - 17 октября | Выбор режима обучения, состава смеси и калибровки. |
| Локальный test | 18 - 31 октября | Оценка зафиксированного решения перед финальным переобучением. |

Для локального test и конкурсного прогноза старт фиксирован в 10:30. Каждая историческая строка использует только факты, доступные к своему старту прогноза. В train включаем строки, у которых метка находится внутри обучающего периода. Заполнение пропусков, масштабирование и признаки с обучаемыми параметрами рассчитываем на train соответствующего временного окна.

В экспериментах выводим WAPE, модуль Relative Bias и их сумму на train и test после фиксации настроек. Дополнительно сохраняем среднюю дневную метрику. Она может иначе ранжировать решения, поскольку каждый день получает одинаковый вес. В приведённых ниже результатах явно указан способ агрегации.

## Пайплайн

1. **Подготовка истории.** Читаем два parquet, восстанавливаем временную сетку по маршрутам и формируем обучающие строки отдельно для каждого горизонта.
2. **Построение признаков.** Рассчитываем лаги цели и статусов, скользящие средние, календарные признаки, сезонные профили и отклонения от исторического уровня. Проверяем варианты с одним, пятью и 48 стартами обучения в сутки. [Описание признаков](docs/feature_engineering.md).
3. **Подбор моделей.** Сравниваем конфигурации на периодах, предшествующих локальному test. В серии с пятью стартами используем несколько последовательных недельных окон. [Протокол экспериментов](docs/model_experiments.md).
4. **Смешивание и калибровка.** Подбираем веса сезонного прогноза и поправку на объём. Для стекинга строим OOF-прогнозы, полученные на датах, следующих за обучением каждой базовой модели. На этих прогнозах обучаем метамодель.
5. **Независимая оценка.** Фиксируем настройки и сохраняем метрики на локальном test до финального переобучения.
6. **Финальное обучение и сабмит.** Перед сборкой сабмита переобучаем модели по всей доступной размеченной истории с учётом выбранных правил окна обучения. Метамодель переобучаем на доступных исторических прогнозах с известными ответами. Собираем прогнозы по исходному `id`, проверяем 8 000 уникальных строк, конечность и неотрицательность значений.

## Что проверим дальше

Следующая серия проверок опирается на Session6 и сравнение двух способов очистки истории. Параметры выбираем на временных окнах до test, затем оцениваем зафиксированный вариант на следующем периоде. [Подробный план пяти экспериментов](docs/next_five_experiments_0326.md).

1. **Поправки по исходной цели.** Сохраним очищенные базовые модели, а модели остатка и оценки смещения обучим на исходных ответах. Это позволит проверить влияние изменённой очисткой обучающей цели на общий объём.
2. **Калибровка по горизонтам.** Проверим регуляризованные поправки отдельно для горизонтов. В сохранённом прогнозе смещения ранних и поздних горизонтов имеют разные направления.
3. **Несколько весов распределения.** Сравним общий вес LightGBM с небольшим числом весов по группам горизонтов, стянутых к общему. Суммарный объём каждого горизонта зафиксируем для оценки вклада распределения между маршрутами.
4. **Прямое обучение долям маршрутов.** Проверим LightGBM с целью, равной доле маршрута в суммарном объёме горизонта. При прогнозировании доли умножим на доступный прогноз общего объёма.
5. **Очистка входов с исходными метками.** Сравним исходную историю, очистку входов и цели, а также очистку только входов. Отдельно оценим нули и крупные фактические объёмы.

Перед следующей посылкой переобучим все входящие в неё модели на всей доступной размеченной истории и сохраним отдельно метрики test, полученные до этого переобучения. Для каждого варианта зафиксируем конфигурацию, файл сабмита и результат соревнования.

Генераторы автономных ноутбуков находятся в [scripts](scripts/). Они перезаписывают одноимённые файлы вместе с сохранёнными выводами. При локальной работе с ноутбуками относительные пути `data/` и `artifacts/` отсчитываются от корня репозитория.

## Структура репозитория

| Папка | Содержимое |
|---|---|
| [data](data/) | Исходная размеченная история и конкурсные строки. |
| [notebooks/eda](notebooks/eda/) | Исследование временных рядов с сохранёнными выводами. Для повторного выполнения потребуется внешний модуль `time_series_analysis`, отсутствующий в репозитории. |
| [best](best/) | Лучший запуск Session6 с результатом 0,326, модели, готовый CSV и восстановление прогноза. |
| [notebooks/stepa](notebooks/stepa/) | Контроль `stepa330`, решение 0,328 и эксперимент с пиками. |
| [notebooks/features](notebooks/features/) | Построение признаков, пилоты и выполненные эксперименты. |
| [notebooks/models](notebooks/models/) | Отдельные модели и маршрутный Ridge. |
| [notebooks/matvey](notebooks/matvey/) | Серия экспериментов с калибровкой, общим объёмом, окнами, функциями потерь и ансамблями. |
| [notebooks/stacking](notebooks/stacking/) | Исторический стекинг и сохранённые выполненные запуски. |
| [stacking](stacking/) | Распределённый стекинг, настройка Ridge и финальный сборщик. |
| [notebooks/clustering](notebooks/clustering/) | Кластерные модели, калибровка и обучаемые поправки. |
| [notebooks/xgb_tuning](notebooks/xgb_tuning/) | Подбор XGBoost, параметры и сравнение очисток. |
| [scripts](scripts/) | Исходники моделей, генераторы ноутбуков и проверки. |
| [artifacts](artifacts/) | Метрики, параметры, исторические прогнозы и отчёты. |
| [submissions](submissions/) | Сохранённые конкурсные прогнозы. |
| [docs](docs/) | Журнал экспериментов, описание признаков, аудит и правила соревнования. |
| [archive](archive/) | Исторические скрипты и результаты решения 0,328. |
