# Как пройти от baseline до сабмита

Цель команды — перейти с 0,330 на закрытом тесте к 0,323. Локальное снижение на 0,007 служит ориентиром. Соответствие между локальной и закрытой метриками устанавливает только посылка на соревнование.

## 1. Подготовьте входы

- Сохраните оригинальный submission команды с результатом 0,330 как отдельный контроль. Он нужен для сравнения на соревновании.
- Распакуйте `results-00_baseline/results.zip` и загрузите папку `baseline_00` в Kaggle Dataset. Внутри нужны `weekly_predictions.parquet`, `full_predictions.parquet`, `network_history.parquet`, `manifest.json`, `submission.csv`, `lags/` и `reports/`. Для следующих этапов достаточно results.zip.
- Для 03 и 04 также подключите исходные `train_solo_track.parquet` и `test_solo_track.parquet`. Скрипт сверяет их хеши с baseline. Подключайте по одной версии одноимённых входных файлов.
- Каждый ноутбук импортируйте отдельно в Kaggle. Используйте Save Version → Save & Run All. После завершения подключайте сохранённый Notebook Output к следующему этапу. Между ноутбуками передаются файлы, а не состояние ядра.

## 2. Первая волна

| Этап | Что подключить | Вычисления | Что сохранить и проверить |
|---|---|---|---|
| 01_calibration | baseline_00 | CPU, без обучения | calibration_settings.json и calibration_report.csv. Повтор контрольного расчёта должен выбрать 7d_x1.0 на tuning и дать около 0,339534 на test против 0,338366 у weekly. |
| 02_total_volume | baseline_00 | CPU, восемь Ridge на этап | volume_settings.json, volume_history.parquet, total_volume_report.csv, submission_total_volume.csv. При положительном весе также volume_future.parquet и volume_models/. |
| 03_windows_features | baseline_00 и исходные данные | GPU, CatBoost | Папка 03_windows_features/. Для продолжения сохраните её целиком. Для 04 и 05 нужны файлы *_selection.json, *_history.parquet и *_future.parquet. |

01, 02 и 03 независимы и могут запускаться одновременно. Сначала проверьте, что 01 воспроизводит таблицу выше. 02 оценивает восемь моделей сетевого объёма, выбирает вес на двух неделях tuning и сравнивает его с нулём. При нулевом весе volume_future.parquet не создаётся и в 05 не требуется.

03 сравнивает recent75 с 42, 56 и 70 днями при одинаковых признаках. На выбранном окне проверяет пики, затем добавление текущего объёма и изменений статусов всей сети. Признаки меняются на h3–h8; остальные горизонты входят в общую метрику. Для новых кандидатов поправка определяется на первых двух неделях, выбор — на следующих двух. Таблица tuning.csv показывает обе недели, WAPE, signed bias и score до и после поправки. Итоговая comparison.csv сопоставляет выбранный вариант и weekly на двух неделях локального test и отдельно по субботам.

### Длинный GPU-запуск

Верхняя граница для 03 — 168 новых fit, для 04 — 120. Фактическое число ниже, когда победитель полностью или частично совпадает с готовым кандидатом. Для ориентира 64 fit этапа 00 заняли в сумме около 4,4 часа по таймерам отдельных моделей. Вычисление признаков и сохранение результата также занимают время.

1. При ограниченной длительности Kaggle-сессии поставьте в ячейке настроек `MAX_NEW_FITS = 24` для первого запуска. `None` запускает весь оставшийся этап.
2. После достижения лимита ноутбук сообщает «Часть завершена». Сохраните версию с папкой `03_windows_features/` или `04_losses/`, в том числе `cache/` и `contract.json`. Прогноз каждой завершённой модели записывается до перехода к следующей.
3. В новой сессии подключите Output предыдущей части. Укажите `RESTORE_DIR` как полный путь к сохранённой папке этапа внутри `/kaggle/input/...`. Сохраните прежние исходные данные, настройки модели и версию CatBoost. Повторите Run All. Завершённые fit пропускаются, незавершённый выполняется снова.
4. В одной и той же рабочей сессии для продолжения достаточно Run All. В новую сессию подключайте только последнюю частичную версию данного этапа. Появление `*_selection.json` **вместе с обоими итоговыми parquet** означает, что этап окончен и следующий ноутбук можно запускать.

## 3. Сравните функции потерь

Запустите 04_losses на GPU. Подключите baseline_00, исходные parquet и завершённый Output 03. Ноутбук читает выбранные в 03 окно и признаки. Он использует прогнозы MAE из 03 и обучает Quantile с alpha 0,55 и 0,60, а также RMSE. Поправка оценивается отдельно у каждой функции по одной и той же процедуре. При равной метрике первым остаётся MAE. Сохраните папку `04_losses/`, в частности *_selection.json, *_history.parquet и *_future.parquet. Работу частями настройте тем же способом, что и в 03.

## 4. Соберите и оцените итог

Запустите 05_ensemble на CPU. Подключите baseline_00 и финальные Outputs 01, 02, 03, 04. В одной сессии достаточно по одному экземпляру каждого результата.

- На tuning сравниваются weekly и победители 03 и 04, затем попарные смеси с долей второй модели 0,25, 0,50 и 0,75. При равенстве сохраняется первый вариант в порядке сравнения.
- Для лучшей смеси проверяются поправки 01 и 02 по отдельности и совместно, если их этапы выбрали ненулевой эффект. После этого выбор записывается в ensemble_selection.json и оценивается на следующих двух неделях.
- Сохраните ensemble_tuning.csv, ensemble_report.csv, ensemble_selection.json и submission.csv. В файле сабмита должно быть 8 000 строк и два столбца — id и y_pred. Он использует финальные прогнозы компонентов, переобученных в 00, 02, 03 и 04 согласно выбранным режимам.
- Основное сравнение — строка `test / all` у weekly и ensemble по daily_score. Дополнительно сравните обе недели, WAPE и субботы. Для контроля 0,338366 локальная цель с выигрышем 0,007 равна 0,331366. Если выигрыш целиком приходится на одну неделю или две субботы, укажите это рядом с цифрой. Для решения об отправке используйте этот отчёт один раз; настройка после его просмотра потребует нового периода проверки.
- Если результаты оправдывают посылку, отправьте submission.csv из 05 и запишите закрытый балл. Если ансамбль выбирает baseline с исходными поправками, файл воспроизводит финальный контроль 00; повторная посылка того же файла полезна только если его балл ещё неизвестен.

Границы одинаковы для маршрутных сравнений: 20 сентября – 3 октября — warmup, 4–17 октября — tuning, 18–31 октября — исторический test. У weekly модель для второй недели test использует факты первой недели, известные к моменту её старта. Независимая от финального переобучения оценка test получена до refit. Эти октябрьские даты уже изучались командой.
