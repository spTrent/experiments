# Маршрутные Ridge на Windows + RTX 4060 Laptop

Полный маршрут от четырёх готовых Kaggle-output до сабмита: [подробная инструкция по сборке стекинга](../STACKING_ASSEMBLY_GUIDE.md).

Для компьютера с 16 ГБ RAM и 8 ГБ VRAM подготовлен автономный `stacking/ridge_tuned_local.ipynb`.
Текущие `stacking/stacking_part_1…4.ipynb` не изменены; их работа в Kaggle продолжается.

## Подготовка Windows

Установите Miniforge для Windows x86_64, если conda ещё нет. В Miniforge Prompt создайте отдельное окружение:

```text
conda create -n ridge4060 -c conda-forge python=3.11 cupy cuda-version=12 numpy pandas scipy scikit-learn pyarrow ipykernel psutil
conda activate ridge4060
python -m ipykernel install --user --name ridge4060 --display-name "Python (ridge4060)"
```

Нужен установленный совместимый драйвер NVIDIA. Отдельный системный CUDA Toolkit при установке CuPy через conda-forge не обязателен: окружение получает необходимые библиотеки. Не устанавливайте поверх этого окружения дополнительные сборки CuPy через pip.

Официальная инструкция CuPy: https://docs.cupy.dev/en/stable/install.html
Miniforge: https://github.com/conda-forge/miniforge

Откройте ноутбук в VS Code и выберите kernel `Python (ridge4060)`. В репозитории исходные parquet находятся в `data` в корне проекта. Если рабочая папка Jupyter — `stacking`, задайте `INPUT_DIR='../data'`; если корень проекта — оставьте `INPUT_DIR='./data'`. При необходимости задайте абсолютный путь Windows в `INPUT_DIR`, например `r'D:\competition\data'`.

## Первый запуск

Оставьте:

```python
MODE = 'oof'
DEVICE = 'cuda'
HORIZONS = (1,2,3,4,5,6,7,8)
BATCH_SIZE = 4
```

Запустите Run All. Проверка CUDA выполняется до загрузки данных. Пять стартов train: 09:30, 10:00, 10:30, 11:00, 11:30 по всей доступной истории, без удаления первых 25% дат.

Горизонты идут последовательно. Таблицы признаков одного горизонта хранятся на диске; CPU-признаки строятся блоками по 8 стартов, корреляционные — по 16. GPU решает до четырёх маршрутных задач одновременно в float64. При нехватке памяти вычислительный пакет делится пополам. Матрица всех маршрутов для обучения Ridge не собирается.

Начните на подключённом питании, с отключённым автоматическим сном Windows. Желательно освободить несколько ГБ RAM и минимум несколько ГБ места на диске под временные таблицы. При желании сначала задайте `HORIZONS=(1,)`, затем верните все восемь: готовый горизонт повторно не вычислится.

## Подбор alpha

Для каждой из 8000 пар маршрут × горизонт проверяются 30 кандидатов в диапазоне 1e-4…1e6; 100 входит в сетку. Это фиксированный логарифмический перебор, не Optuna.

Три tuning-недели: 30 августа–5 сентября, 6–12 и 13–19 сентября 2025. В каждом fit метки train строго раньше недели; лаги, заполнение пропусков и стандартизация обучаются заново на прошлом. Разложение матрицы переиспользуется для всех alpha.

Выбор — минимальное среднее недельных WAPE + |Relative Bias|. При нулевом факте недели используется MAE с явной отметкой в таблице параметров. Alpha фиксируется до первого OOF, затем не подбирается заново.

OOF: 27 сентября–3 октября, 4–10 октября, 11–17 октября. Прогнозы только из 10:30. После каждого этапа выводятся метрики train/held_out; отдельные времена сохраняются в timings.jsonl. Численное решение проверяется относительно sklearn на первых двух маршрутах каждого этапа прогноза.

## Сохранение и продолжение

`ridge_output/ridge_tuned_<id>/` содержит manifest, параметры, checkpoint каждого пакета и прогнозы. Повторный Run All с теми же данными, кодом и версиями библиотек продолжает расчёт. Незавершённый пакет и временные признаки могут вычисляться заново. Изменение BATCH_SIZE не портит результаты, но незавершённые этапы могут перерассчитаться с новой разбивкой пакетов.

Не удаляйте папку `ridge_output`. `ridge_cache` — временная папка; после нормального завершения горизонта очищается. Не запускайте два экземпляра в один OUTPUT_DIR.

После каждого горизонта обновляется `ridge_tuned_<id>_export.zip`. Это компактный экспорт для Kaggle: manifest, выбранные alpha и прогнозы с границами обучения. Подробные tuning-checkpoint остаются локально и нужны для продолжения.

## Подключение к работающему стекингу

После завершения всех восьми горизонтов загрузите экспорт как Kaggle Dataset. Внутри Dataset должна быть распакованная папка `ridge_tuned_<id>` с manifest.json и predictions. Если интерфейс оставил ZIP как единственный файл, распакуйте его перед созданием Dataset.

Не подключайте несколько версий экспорта одновременно. Сборщик проверяет исходные файлы по хешам, CODE_ID исходного стекинга, версию локального ноутбука, временные границы, все ключи и совпадение фактов.

Используйте **новые** `stacking_tuned_part_1…4.ipynb` для следующих этапов. Они сохраняют CODE_ID исходных баз и используют готовые файлы. Старые четыре ноутбука завершат OOF без изменений.

1. Часть 1, `MODE='assemble'`: подключить исходные parquet, output четырёх исходных частей и локальный экспорт. Сравниваются четыре состава: без маршрутных Ridge, с фиксированными, с подобранными, с обоими. Все три вида метамоделей сохранены: 28 исходных конфигураций + 18 вариантов калибровки лучшего кандидата = 46 кандидатов. Новая колонка — `five_starts__route_ridge_tuned`.
2. Все четыре новые части, `MODE='evaluate', ROLE='worker'`: подключить результат новой сборки и готовые исходные output. Досчитываются только отсутствующие базы победителя. Внешний Ridge на Kaggle не обучается.
3. Локально `MODE='evaluate'`: строятся прогнозы 18–31 октября с зафиксированными alpha. Обновить Dataset новым экспортом. Часть 1, `MODE='evaluate', ROLE='collect'`: сохранить независимую оценку test.
4. Все четыре новые части, `MODE='submit', ROLE='worker'`; локально `MODE='submit'` для extra (25–31 октября) и full (1 ноября). Подключить отчёт test, новую сборку и все предыдущие output. Обновить Dataset экспортом локального submit.
5. Часть 1, `MODE='submit', ROLE='collect'`: результат `submission_tuned.csv`.

Новые метаданные и калибровки хранятся в `meta_tuned`, старый `meta` и `submission.csv` не заменяются. Внешний Ridge применяется только если он входит в выбранный состав. Не выбирайте настройки по test: победитель фиксируется на OOF.

## Проверки

`scripts/check_tuned_ridge.py` проверяет синтаксис автономных ноутбуков, alpha-сетку относительно sklearn, нулевые объёмы, деление пакета при нехватке памяти, реальную подготовку признаков на небольшой искусственной панели, OOF/test/extra/full, восстановление, очистку временных файлов и подключение к сборщику. Локально проверен CPU-путь; реального замера на RTX 4060 ещё нет.
