# Прогноз объёма отправлений по маршрутам RWB

Решение задачи прогнозирования `target_1h` для 1 000 маршрутов на восемь получасовых горизонтов. В 10:30 формируем прогнозы с 11:00 до 14:30. Итоговый файл содержит 8 000 строк с колонками `id,y_pred`.

**Лучший результат команды на Public составляет 0,330.** Его получил ансамбль CatBoost и сезонного профиля с поправкой на общий объём. Код, параметры и сохранённые выводы находятся в [ноутбуке stepa330](notebooks/stepa/stepa330.ipynb).

## Лучшее решение

Для каждого из восьми горизонтов обучаем отдельную модель CatBoost. Признаки описывают текущую нагрузку маршрута, недавнюю динамику цели и шести статусов, календарь и исторические значения соответствующего получасового слота. Режим `recent75` использует последние 75% доступного периода обучения и был выбран на периоде подбора.

Прогноз собираем в три шага.

1. Для горизонта h1 используем CatBoost. Для h2-h8 смешиваем 70% прогноза CatBoost и 30% сезонного профиля `profile28`.
2. Профиль строим по тому же получасовому слоту за предыдущие 28 дней. Исторические значения масштабируем с учётом текущего уровня маршрута за последние сутки.
3. К объединённому прогнозу восьми горизонтов применяем аддитивную поправку, оценённую по историческим ошибкам. Она уменьшает систематическое смещение общего объёма.

| Оценка stepa330 | Значение |
|---|---:|
| Public соревнования | **0,330** |
| WAPE на локальном test | 0,321816 |
| Модуль Relative Bias на локальном test | 0,011498 |
| WAPE + модуль Relative Bias на локальном test | 0,333315 |
| Средняя дневная метрика на локальном test | 0,340499 |

Public указан по результату посылки команды. Локальные значения взяты из сохранённых выводов ноутбука. Независимая оценка test получена до финального переобучения. Этот исторический период уже использовался в нескольких экспериментах проекта, что ограничивает независимость последующих сравнений на тех же датах. [Результаты stepa330](notebooks/stepa/stepa330.ipynb).

## Данные и проверка качества

Размеченная история содержит 4 630 000 строк с 28 июля по 1 ноября 2025 года, 10:30. Для каждого маршрута доступны временная метка, цель `target_1h` и шесть статусов. Конкурсный прогноз строится на 1 ноября 2025 года. Исходные файлы и описание задачи доступны в [data](data/) и [материалах соревнования](docs/competition/).

Метрика соревнования складывается из WAPE и модуля Relative Bias. WAPE равен сумме абсолютных ошибок, делённой на суммарный фактический объём. Relative Bias равен сумме ошибок со знаком, делённой на тот же объём. Поэтому при выборе решения учитываем одновременно точность маршрутных прогнозов и смещение общего объёма. Меньшее значение метрики соответствует лучшему результату.

В `stepa330` используем хронологическое разбиение.

| Период | Даты 2025 года | Назначение |
|---|---|---|
| Train | 28 июля - 3 октября | Обучение базовых моделей с учётом выбранного окна истории. |
| Подбор | 4 - 17 октября | Выбор режима обучения, состава смеси и калибровки. |
| Локальный test | 18 - 31 октября | Оценка зафиксированного решения перед финальным переобучением. |

Для локального test и конкурсного прогноза старт фиксирован в 10:30. Каждая историческая строка использует только факты, доступные к своему старту прогноза. В train включаем строки, у которых метка находится внутри обучающего периода. Заполнение пропусков, масштабирование и признаки с обучаемыми параметрами рассчитываем на train соответствующего временного окна.

В экспериментах выводим WAPE, модуль Relative Bias и их сумму на train и test после фиксации настроек. Дополнительно сохраняем среднюю дневную метрику. Она может иначе ранжировать решения, поскольку каждый день получает одинаковый вес. В приведённых ниже результатах явно указан способ агрегации.

## Пайплайн

1. **Подготовка истории.** Читаем два parquet, восстанавливаем временную сетку по маршрутам и формируем обучающие строки отдельно для каждого горизонта.
2. **Построение признаков.** Рассчитываем лаги цели и статусов, скользящие средние, календарные признаки, сезонные профили и отклонения от исторического уровня. Проверяем варианты с одним, пятью и 48 стартами обучения в сутки. [Описание признаков](docs/feature_engineering.md).
3. **Подбор моделей.** Сравниваем конфигурации на периодах, предшествующих локальному test. В серии с пятью стартами используем несколько последовательных недельных окон. [Протокол экспериментов](docs/model_experiments.md).
4. **Смешивание и калибровка.** Подбираем веса сезонного прогноза и поправку на объём. Для стекинга строим OOF-прогнозы, полученные на датах, следующих за обучением каждой базовой модели. На этих прогнозах обучаем метамодель.
5. **Независимая оценка.** Фиксируем настройки и сохраняем метрики на локальном test до финального переобучения.
6. **Финальное обучение и сабмит.** Перед сборкой сабмита переобучаем модели по всей доступной размеченной истории с учётом выбранных правил окна обучения. Метамодель переобучаем на доступных исторических прогнозах с известными ответами. Собираем прогнозы по исходному `id`, проверяем 8 000 уникальных строк, конечность и неотрицательность значений.

## Воспроизведение

Обучение запускается пользователем в Kaggle.

1. Импортируйте [stepa330.ipynb](notebooks/stepa/stepa330.ipynb).
2. Подключите датасет с `train_solo_track.parquet` и `test_solo_track.parquet` из [data](data/).
3. Включите GPU. При необходимости укажите каталог датасета в переменной `DATA` первой ячейки.
4. Выполните **Save & Run All**. Ноутбук проведёт подбор, оценку и финальное обучение. Результат сохранится в `submission_team_scaled_experiments.csv`.

Для распределённого стекинга порядок запуска, входные артефакты и сборка четырёх частей описаны в [инструкции](stacking/STACKING_ASSEMBLY_GUIDE.md). Генераторы автономных ноутбуков находятся в [scripts](scripts/). Они перезаписывают одноимённые файлы вместе с сохранёнными выводами. При локальной работе с ноутбуками относительные пути `data/` и `artifacts/` отсчитываются от корня репозитория.
