# Лучшие параметры из xgb-tuning (1).ipynb

Источник: `/Users/sptrent/Downloads/xgb-tuning (1).ipynb`, завершённый Kaggle-запуск `20261110T012435627774Z`. Извлечены все 240 завершённых попыток: по 30 на каждый горизонт. Для каждого горизонта выбрана минимальная MAE на val; test не участвовал в выборе.

- `best_params.json`: все восемь победителей, настройки исходного запуска и SHA-256 ноутбука.
- `best_h1.json` … `best_h8.json`: отдельные горизонты.
- `summary.csv`: номера попыток, MAE на val, число деревьев и test-метрики.

`params.n_estimators` — исходный лимит деревьев попытки. `selected_trees` — выбранное число деревьев после early stopping. В `refit_params` лимит заменён этим числом: это параметры для последующего обучения с зафиксированным числом деревьев. При таком обучении на всей истории early stopping отключается.

Параметры попыток и MAE на val извлечены из точных строк Optuna. Остальные метрики взяты из округлённых таблиц ноутбука. Число деревьев и MAE сверены с таблицами победителей.

Цель обучения — `target_1h / 100000`, objective — `reg:absoluteerror`. Прогноз возвращается в исходный масштаб и ограничивается снизу нулём. Фиксированные настройки модели: `tree_method='hist'`, `device='cuda'`, `enable_categorical=True`, `max_cat_to_onehot=1`, `eval_metric='mae'`; seed и число потоков сохранены в `config` общего JSON. Для route_id нужен тот же справочник категорий и тот же порядок входных признаков; эти JSON не заменяют кэш признаков или сохранённые модели.

Независимая от подбора оценка test получена до переобучения на всей истории; эти даты ранее изучались в проекте. Здесь обучение не выполнялось и submission не создавался.
