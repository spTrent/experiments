# Кластеризация маршрутов

Основной файл: [cluster_catboost_ridge.ipynb](cluster_catboost_ridge.ipynb). Ноутбук автономный, обучение запускается пользователем в Kaggle.

Эксперимент с коррекцией bias: [cluster_catboost_calibration.ipynb](cluster_catboost_calibration.ipynb). Общий CatBoost и 8 кластеров, фиксированные depth=6 / 600 деревьев / learning_rate=0.05 / MAE. Сравниваются восемь способов: исходные прогнозы, общий множитель, поправки по горизонтам с усадкой и без, поправки по группам с усадкой и без, поправки по парам группа × горизонт с усадкой и без. Группы калибровки (по умолчанию 8) строятся до val и фиксируются по route_id для всех этапов, независимо от переобучения кластеров базовых моделей. Малые группы и нулевые суммы используют общий или горизонтный fallback. Карта сохранена в calibration_groups.csv и calibration_frozen.json. Первые 7 дней val оценивают коэффициенты, следующие 7 выбирают способ; между блоками базовые модели переобучаются. Перед test выбранный способ переоценивает коэффициенты на всех 14 днях временных OOF-прогнозов и фиксируется. После независимой оценки базовые модели обучаются на всей истории, а коэффициенты того же способа обновляются на доступных OOF val + бывшего test; прежняя оценка относится к прежним моделям и коэффициентам. Сохраняются `submission.csv` и `submission_raw.csv`. Калибровка меняет WAPE, поэтому устранение bias не гарантирует итоговые 0.32. Старый test уже изучен; результат не является новым слепым подтверждением.

## Что сравниваем

| Вариант | Модели на каждый горизонт | Назначение |
| --- | --- | --- |
| Ridge global | Одна общая GPU Ridge | Линейный контроль |
| CatBoost global | Один общий CatBoost | Проверка нелинейного метода |
| CatBoost, 8 кластеров | По модели на крупную группу | Грубая сегментация |
| CatBoost, 16 кластеров | По модели на крупную группу | Более узкая специализация |

Модели отдельных горизонтов независимы. Кластеризация общая для восьми горизонтов. Группы меньше 10 маршрутов используют общую модель, обученную на всех маршрутах, а не на объединении только маленьких групп. Метка таких маршрутов в отчёте — −1.

Сравнение общего и кластерных CatBoost проверяет пользу сегментации. Сравнение CatBoost с Ridge оценивает методы целиком: кроме нелинейности различаются и функции потерь. Признаки, нормировка и временные периоды одинаковы. Используется новый компактный набор признаков; это не точное повторение прежнего эксперимента с 8000 Ridge.

## Запуск и обязательный GPU

1. Загрузить ноутбук в Kaggle и подключить исходные `train_solo_track.parquet` и `test_solo_track.parquet`.
2. Включить NVIDIA GPU в настройках сессии. Оставить `TASK_TYPE='GPU'`.
3. Проверить наличие CuPy для CUDA сессии. Если пакета нет, установить совместимую сборку: например, `cupy-cuda12x` для CUDA 12; не устанавливать несколько сборок CuPy одновременно.
4. Выполнить Run All. Выходы сохраняются в `/kaggle/working/cluster_experiment_<hash>/`, архив — рядом.

Перед чтением данных проверяются видимость GPU для CatBoost и выполнение линейной алгебры CuPy. CPU-режим запрещён, автоматического fallback нет. Все прогнозные модели обучаются на GPU: CatBoost через CUDA, Ridge через CuPy. Ridge накапливает взвешенные матрицы пакетами в float64 и решает регуляризованную систему с нештрафуемым свободным членом. В артефакте сохраняются обычные массивы коэффициентов; функция прогноза Ridge также использует CuPy.

KMeans, подготовка признаков, стандартизация, расчёт метрик и сохранение файлов остаются на CPU. GPU не устраняет потребность в RAM: общая модель получает миллионы строк. Обработка последовательная; время и пиковая память на Kaggle пока не измерены.

## Пайплайн

1. **Проверка данных.** Полная получасовая панель без повторов и пропусков; конкурсные запросы соответствуют маршрутам и восьми горизонтам после последнего cutoff в 10:30.
2. **Временное разбиение.** Train — история до val, все получасовые старты. Val — 14 полных дней перед test. Test — последние 14 полных дней, для которых доступны все горизонты. Val/test оцениваются только в 10:30. Для данных проекта это 4–17 и 18–31 октября 2025; даты вычисляются автоматически. Метки обучения строго раньше границы следующего периода.
3. **Профили маршрутов.** Средняя цель маршрута, ограниченная снизу единицей, задаёт масштаб. Для кластеризации используются нормированные суточный и недельный профили, изменчивость, доля нулей, частота скачков и 95-й процентиль. Дескрипторы стандартизируются перед KMeans. Абсолютный объём не входит в расстояние между маршрутами.
4. **Признаки прогноза.** Последние значения цели и статусов, изменения статусов, скользящие средние цели, сезонные лаги на 1/7/14/28 дней, циклический календарь и логарифм масштаба маршрута. Недоступные ранние лаги имеют нулевое значение и индикатор доступности. Динамические признаки используют историю только до собственного cutoff.
5. **Нормировка и обучение.** Объёмные признаки и цель делятся на масштаб маршрута. Веса строк пропорциональны масштабу. Для CatBoost MAE с такими весами соответствует абсолютной ошибке в исходных единицах с общим множителем; штраф за bias эта функция потерь напрямую не оптимизирует. Ridge использует взвешенную квадратичную ошибку и стандартизированные признаки, alpha = lambda × число обучающих строк. Прогнозы обрезаются снизу нулём.
6. **Подбор только на val.** Для Ridge проверяются пять lambda. Для CatBoost — две фиксированные конфигурации глубины и числа деревьев. На каждый горизонт выбирается одна конфигурация, общая для всех кластеров этого варианта. Затем по агрегированной метрике val выбирается вариант целиком. Выбор сохраняется в `selection_frozen.json` до оценки test.
7. **Независимая оценка.** Все четыре варианта заново обучаются на истории до test, включая бывшую val. Масштабы и кластеры пересчитываются по этой обучающей истории. Выводятся train/test, метрики по горизонтам и прогнозы каждой строки test. Победитель по результатам test автоматически не меняется.
8. **Полное обучение и сабмит.** Все модели выбранного по val варианта, включая fallback при необходимости, переобучаются на всей доступной размеченной истории. Используются все старты с известной меткой, включая бывшие val/test и последний неполный день. Кластеры и масштабы также пересчитываются. После этого создаётся `submission.csv` с исходным порядком id.

При каждом новом этапе кластерные метки могут измениться. Это допустимо: настройки выбраны на уровне варианта и горизонта, а не для конкретного номера кластера.

## Метрика и интерпретация

`WAPE + |Relative Bias| = (sum(abs(pred − y)) + abs(sum(pred − y))) / sum(y)`.

Ошибки суммируются в исходных единицах по всем строкам; метрики маршрутов или кластеров не усредняются. На этапе подбора показываются train/val, а test закрыт. На этапе независимой оценки показываются train/test. При полном обучении показываются full_in_sample и сохранённые train/test прежних оценочных моделей.

**Независимая оценка test получена до переобучения на всей доступной размеченной истории.** Результаты появятся после пользовательского запуска; настоящего обучения и измерения качества при подготовке ноутбука не проводилось. Этот календарный test ранее использовался в проекте и не является новым слепым holdout. Train оценивается на всех стартах, test — только в 10:30; разрыв нельзя полностью объяснять переобучением.

Val/test моделируют последовательные ежедневные прогнозы: наблюдённая история предыдущих дней доступна в признаках следующих дней. Это не прогноз всех 14 дней из одной общей точки времени.

## Артефакты и продолжение

- `validation_summary.csv`, `search_metrics.csv`, `selection_frozen.json`: подбор и выбранный вариант.
- `independent_metrics.csv`, `independent_metrics_by_horizon.csv`: train/test до полного обучения.
- `test_h*_*.parquet`: прогнозы test для диагностики маршрутов и дней.
- `route_profiles_*.csv`, `segments_*.joblib`: профили, метки, масштабы и кластеризация каждого этапа.
- `final_model_h*.joblib`, `segments_full.joblib`: модели и преобразования финального варианта.
- `full_in_sample_metrics.csv`, `submission.csv`, `evaluation_note.txt`: финальный результат и оговорки об оценке.

Завершённые этапы сохраняются по варианту и горизонту. При повторном Run All с теми же данными и настройками они переиспользуются; незавершённая пара пересчитывается. Для новой Kaggle-сессии нужно восстановить папку результата. Изменения кода, данных и основных настроек меняют хеш каталога. Старые CPU-результаты не смешиваются с новой GPU-версией. Не запускать одновременно два процесса в одну папку.

## Идеи следующих экспериментов

1. **Сначала оценить пользу сегментации.** Если общий CatBoost стабильно не хуже кластерных вариантов на временных val, отказаться от отдельных моделей по группам. Увеличивать число кластеров без такого выигрыша не стоит.
2. **Добавить номер кластера и профиль в общую модель.** Общий CatBoost с категориальной меткой кластера сможет учитывать различия групп, сохраняя все данные для обучения. Это отдельный контроль против жёсткого разделения выборки.
3. **Общая модель плюс локальная поправка.** Учить кластерную модель на остатках общих прогнозов, полученных вне обучающей выборки по временным фолдам. Силу поправки выбирать на val, для слабых групп уменьшать до нуля.
4. **Несколько временных проверок.** Проверять выигрыш на последовательных окнах до финального test. Следить за устойчивостью размеров групп и назначений маршрутов, а не только за одной удачной двухнедельной val.
5. **Профиль около рабочего cutoff.** Сравнить текущий полный суточный профиль с поведением около 10:30 и в часы прогнозных целей. Отдельно проверить обучение на пяти стартах вокруг 10:30; не смешивать эффект изменения стартов с эффектом кластеризации в одном сравнении.
6. **Калибровка смещения.** Подбирать глобальный или групповой коэффициент по временным OOF/val-прогнозам, с усадкой групповых коэффициентов к общему. Не вычислять поправку по test.
7. **Диагностика экстремальных ошибок.** На сохранённых прогнозах определить крупнейшие вклады маршрутов, дней и горизонтов, особенно h4. Проверить, действительно ли сегментация устраняет нестабильные прогнозы, а не просто улучшает среднее.
8. **Иные нелинейные модели.** После проверки самой сегментации сравнить LightGBM/XGBoost на тех же группах и временных периодах. Не расширять одновременно сетку моделей, признаков и числа кластеров на одной короткой val.

Все новые настройки выбирать на периодах до test. После изучения текущего test дальнейшие улучшения требуют нового holdout либо заранее определённых дополнительных временных проверок.

## Исходники и проверки

Генератор: `scripts/build_cluster_experiment_notebook.py`. Логика: `scripts/cluster_experiment/runtime.py`. Проверки: `scripts/check_cluster_experiment.py`. Пути относительно корня репозитория; для запуска в Kaggle эти файлы не нужны.

Проверяются формат ноутбука, синтаксис, отсутствие assert/комментариев/докстрингов, временные границы, причинность признаков и сегментации, запрет открытия test при подборе, продолжение запуска, fallback, агрегация метрики и порядок submission. CatBoost/Ridge в проверке полного сценария заменены тестовыми заглушками. Реальное выполнение CUDA требует проверки пользовательским запуском на GPU.
