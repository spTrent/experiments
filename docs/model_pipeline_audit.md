# Аудит модельного пайплайна

Проверены 12 модельных ноутбуков: direct/residual для XGBoost, CatBoost, LightGBM, Random Forest, Ridge и Prophet. Область проверки — эти ноутбуки, общие шаблоны scripts/five_starts_features.py и scripts/five_starts_models.py, генератор, проверки и структура новых артефактов. Старые исследовательские ноутбуки eda, local_stacking, team_scaled_catboost и отдельный feature_engineering не входят в этот аудит.

## Исправления

1. Базовые FE-parquet больше не содержат корреляционные признаки, обученные по последнему fold. Теперь в этих колонках NaN; значения обязательно рассчитываются отдельно по train конкретного этапа. До изменения текущий цикл обучения перезаписывал их правильно, но самостоятельное повторное использование исходных parquet могло дать утечку. Метаданные явно описывают режим хранения.
2. Поле model_info_through в tuning-прогнозах теперь учитывает весь период, использованный для выбора гиперпараметров. Добавлены fit_labels_before, selection_labels_through и is_unbiased_oof=False. Прежняя дата учитывала только val отдельного fold и могла ошибочно позволить использовать эти прогнозы как независимые данные для стекинга.
3. Прогноз Prophet возвращается в исходный порядок строк после стабильной сортировки по ds. Это защищает перемешанные входные строки и residual-смещения от неправильного сопоставления.
4. NaN и бесконечные прогнозы отклоняются до clipping. Ранее отрицательная бесконечность могла превратиться в ноль.
5. Добавлены явные проверки непустых train/val/tuning/test и временных границ по времени метки. Обучение прекращается при их нарушении.
6. Удаляются оставшиеся ссылки на модель и оценочный frame после горизонта, чтобы следующий fit не удерживал предыдущую модель в памяти.
7. Добавлены два недостающих LightGBM-ноутбука. Для бустингов отключено переключение малых категорий на one-hot; RF/Ridge/Prophet используют двоичные коды маршрута.
8. Добавлена ранняя проверка наличия зависимостей до построения признаков. LightGBM запускается на CPU по умолчанию; GPU требует подходящей сборки библиотеки.

## Временной протокол

| Fold | Train | Val | Tuning |
|---|---|---|---|
| 1 | 28 июля — 22 августа 2025 | 23–29 августа | 30 августа — 5 сентября |
| 2 | 28 июля — 29 августа 2025 | 30 августа — 5 сентября | 6–12 сентября |
| 3 | 28 июля — 5 сентября 2025 | 6–12 сентября | 13–19 сентября |

Test: 18–31 октября 2025. Train использует пять стартов; остальные периоды — 10:30. Проверяется timestamp метки, а не только cutoff строки. Первые строки без profile28 исключены, как в исходных экспериментах.

Для каждого trial имputer/scaler обучаются заново по train; early stopping бустингов использует только val. Optuna использует только три tuning-недели. Все восемь конфигураций фиксируются до независимой оценки. Оценочная модель и словарь лагов обучаются по истории строго до test; full refit идёт после сохранения оценки.

Независимая оценка test получена до переобучения на всей доступной истории. Фактические метрики появятся только после пользовательского запуска: аудит не обучал модели и не создавал настоящие результаты соревнования.

На test модель фиксирована, но признаки ежедневно используют наблюдения до текущего cutoff. Например, прогноз 20 октября вправе использовать факты 19 октября. Это соответствует ежедневному прогнозу из 10:30 на четыре часа вперёд. Это не оценка единого прогноза на 14 дней без поступления новых фактов.

## Выполненные проверки

- Синтаксис и формат всех 12 ноутбуков; точное AST-соответствие исполняемых ячеек общим проверенным шаблонам; разные ALGORITHM, RESIDUAL и MODEL_NAME.
- Реальные parquet: 4 630 000 строк, 1000 маршрутов, 4630 временных точек; отсутствие пропусков и дубликатов ключей, полная получасовая панель, соответствие 8000 строк submission ожидаемым маршрутам/горизонтам.
- Подмена всех значений после cutoff: для каждого из пяти стартов и восьми горизонтов признаки прошлого остаются прежними.
- Подмена данных начиная с val каждого из трёх folds: train-словарь корреляционных лагов и train-признаки не меняются.
- Подмена таргета начиная с 20 сентября: признаки всех трёх tuning-периодов на восьми горизонтах не меняются.
- Независимые формулы для недавних лагов, среднего 12 точек, суточного сезонного лага, сетевой суммы, profile28 и WAPE + абсолютный Relative Bias.
- Синтетическая известная задержка: поиск корреляции восстанавливает лаг; источник позже cutoff недоступен, допустимый сосед окна рассчитан правильно.
- Компактное кодирование 1000 маршрутов: десять битов, уникальные коды, нулевой код неизвестного маршрута; сериализация preprocessing сохраняет результат.
- Imputer/scaler не используют статистики входной оценочной выборки.
- Все 12 адаптеров fit/predict/save проверены с тестовыми заменами оптимизаторов: цели direct/residual, категориальные типы, early stopping, число деревьев, порядок Prophet, масштаб прогноза, metadata и сохранение файлов.
- Полный управляющий цикл Optuna → фиксация параметров → evaluation → full refit выполнен на синтетических данных с подставными моделями. Проверены число вызовов, отсутствие test-меток в обучении до refit и включение всех пригодных меток в refit.
- Проверены порядок id, формат submission, шесть рабочих папок, восемь best_hN.json, отчёты и оба ZIP-архива.
- Проверены запрет assert, комментариев и docstring в кодовых ячейках и синтаксис вспомогательных скриптов.

Команды воспроизведения:

```bash
python scripts/check_model_notebooks.py
python scripts/audit_model_notebooks.py
```

Эти проверки не запускают оптимизацию параметров настоящих моделей. Их fit заменён тестовыми реализациями; preprocessing рассчитывается реально.

## Ограничения и интерпретация

В проверенном временном протоколе не обнаружено передачи test-меток в обучение или подбор до финального refit. Это результат анализа и перечисленных проверок, не гарантия отсутствия любых ошибок в любом окружении.

Полное обучение на реальных данных, GPU-ядра, время выполнения, сходимость оптимизаторов, пиковая RAM/VRAM и сериализация настоящих обученных моделей не проверялись. В локальном окружении нет Prophet и LightGBM; их интерфейсы сверены с официальными исходниками/документацией, а адаптеры проверены тестовыми заменами. Установленные при аудите версии: NumPy 2.5.4, pandas 3.1.1, scikit-learn 1.9.1, XGBoost 3.4.1, CatBoost 1.2.10, Optuna 5.0.0. Проверки не подтверждают совместимость каждой версии, разрешённой диапазонами requirements.

Общий Prophet на горизонте — аддитивная модель всех маршрутов с общим трендом и сезонностями. Двоичный код маршрута не даёт отдельного свободного коэффициента каждой категории в Ridge/Prophet. Это ограничение выразительности, а не утечка. Проверка RAM Prophet приблизительная и не гарантирует отсутствие OOM.

Словарь корреляций использует метки train, а затем применяется и к самому train. Поэтому train-метрики являются обучающими и могут быть оптимистичными. На val/tuning/test используются только словари, построенные до соответствующих периодов.

Tuning-прогнозы выбраны по тем же tuning-неделям, поэтому не являются независимыми OOF. Test уже использовался в проекте: его нельзя называть новым слепым holdout. Если выбирать алгоритм, признаки или настройки по этому test, его оценка перестаёт быть независимой от такого выбора. Важности полного refit тоже нельзя использовать для подбора признаков с заявлением независимости того же test.

Справочник route_id общий для истории, не использует таргет; проверенная полная панель содержит все маршруты с первого дня. Набор категорий не извлекает информацию о будущих целевых значениях.
