# Очистка исходных рядов и фиксированный XGBoost

Используйте `xgb_cleaning.ipynb`. Это автономная версия прикреплённого `xgb-tuning (1).ipynb`: формулы всех исходных признаков перенесены, Optuna и early stopping удалены. Параметры для h1–h8, включая сохранённое число деревьев, встроены из `best_params/best_params.json`, секция `refit_params`. JSON отдельно подключать к Kaggle не требуется.

## Порядок работы

1. Проверка GPU, исходной получасовой панели и конкурсных запросов.
2. Причинная очистка `target_1h` и `status_1`–`status_6`.
3. Построение прежних признаков из очищенных рядов и сохранение нового кэша.
4. Оценочное обучение двух вариантов: все 48 получасовых стартов и девять стартов 08:30–12:30. Каждый вариант содержит восемь отдельных моделей. Обучающая цель очищена, метрика считается по исходному таргету.
5. Сравнение четырёх калибровок на val, фиксация типа и оценка train/test.
6. Полное переобучение всех 16 XGBoost на всей доступной размеченной истории и выпуск сабмитов.

Импортируйте ноутбук в Kaggle, подключите оба parquet, включите GPU и выполните Run All. Обучение запускает пользователь. `DATA_DIR=None` автоматически ищет единственную папку с train/test. Для переноса признаков между сессиями подключите Output прежнего запуска как Dataset; совместимый manifest находится автоматически, либо задайте `CACHE_INPUT`. Старые признаки без очистки несовместимы. Самостоятельное изменение формул очистки требует пересборки ноутбука генератором или увеличения `PIPELINE_VERSION`, чтобы исключить старый кэш.

## Очистка

Робастный rolling z-score в `log1p`-масштабе считается отдельно для каждого маршрута, поля и получасового слота суток. Окно — предыдущие 28 дней этого слота, минимум 14 дней. Текущая точка не входит в статистики. Центр — медиана окна, MAD — медиана абсолютных отклонений всех наблюдений окна от той же медианы. Масштаб равен `max(1.4826 × MAD, 0.25)`, фиксированный порог — 4. Верхние и нижние выбросы заменяются `expm1` исторической медианы. Параметры не перебираются. Версия кэша `xgb_raw_cleaning_log_slot_mad_v2` исключает повторное использование признаков прежнего фильтра со средним и стандартным отклонением. Статистики используют предыдущие исходные наблюдения; начальный период без 14 наблюдений сохраняется.

Временные строки сохраняются. Нули могут заменяться как нижние выбросы; их число выводится отдельно. Реальные редкие события тоже могут быть сглажены, поэтому результат проверяется по исходным фактам. На val/test доступные к cutoff наблюдения также очищаются причинно. Отдельно сохраняются `y` для оценки и `y_clean` для обучения; обе колонки исключены из признаков.

## Разбиение и калибровка

Как в источнике: последние семь полных прогнозных дней — test; предыдущие дни делятся хронологически 80/20 на train/val. На train граница применяется к timestamp метки, чтобы цель не переходила в val. На val/test используется только старт 10:30. Квинтили объёма маршрута и оценочный словарь корреляционных лагов строятся только по train.

| Калибровка | Правило |
|---|---|
| none | Без изменений |
| global | Общая сумма исходных целей / сумма прогнозов |
| grouped | Множитель для горизонта × квинтиля объёма маршрута; стягивание к общему с фиксированными 2 000 псевдостроками |
| nonlinear | Общая изотоническая функция на 128 квантильных корзинах, взвешенных числом строк; за границами — пропорциональная экстраполяция |

На первой половине val обучаются калибраторы, на второй выбирается тип по общей WAPE + |Relative Bias|. Выбор выполняется отдельно для двух вариантов обучения. Затем четыре калибратора переоцениваются на полном val, выбранный тип сохраняется. Настройки методов фиксированы, гиперпараметры XGBoost и очистки не перебираются.

После каждого fit выводятся WAPE, |Relative Bias| и сумма на train/test. Дополнительно есть одинаковый train по стартам 10:30 для сопоставления вариантов и общая таблица четырёх калибровок. После выбора калибровки отчёт val на всём val является оценкой на данных её обучения, а независимый от fit калибратора результат выбора сохранён в `calibration_selection.csv` на поздней половине val.

Независимая от выбора на val оценка test получена **до полного переобучения**. Октябрьские даты ранее изучались в проекте и не являются новым слепым периодом. Test не меняет выбранный тип калибровки. После оценки XGBoost и корреляционный словарь переоцениваются на всей доступной размеченной истории. Калибраторы фиксируются по val-прогнозам моделей до refit; по in-sample прогнозам полной модели они не обучаются. Перенос поправки после полного refit остаётся практическим ограничением.

## Результаты запуска

В `/kaggle/working/xgb_cleaning/` лежат `submission_all_halfhours_selected.csv` и `submission_nine_starts_selected.csv`. В `runs/<дата>/` сохраняются:

- восемь CSV: `submission_<вариант>_<калибровка>.csv`;
- `model_metrics_before_refit.csv` — исходные train/val/test метрики каждой модели;
- `calibration_selection.csv` — сравнение типов на поздней половине val;
- `independent_calibrated_metrics_before_refit.csv` — все четыре калибровки на train/val/test до полного refit;
- `calibrators.json`, `route_volume_groups_train.csv`, фиксированные параметры, колонки признаков и словари лагов;
- модели до/после refit, отчёт очистки, примеры замен, оценочные и конкурсные прогнозы.

Сборщик: `.venv/bin/python scripts/build_xgb_cleaning_notebook.py`. Он использует прикреплённый исходник из Downloads и текущий `best_params/best_params.json`.

Локально проверены исполнение всех стадий на реальном фрагменте с заменой обучения заглушкой, восемь CSV и порядок исходных id, отсутствие цели в признаках, соответствие колонок, обнуление суммарного смещения общей калибровкой, восстановление искусственного всплеска и неизменность очищенного префикса при добавлении будущих наблюдений. Настоящее обучение локально не запускалось. Полная сводка замен новым фильтром без обучения сохранена в `artifacts/xgb_cleaning_audit/raw_cleaning_mad_summary.csv`. Прежний `raw_cleaning_summary.csv` относится к фильтру со средним и стандартным отклонением и не описывает текущую очистку.
