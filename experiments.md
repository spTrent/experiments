# Эксперименты для Kaggle

## Три следующих эксперимента

- [ ] **1. Случайный лес как самостоятельная модель.** Запустить `random_forest_direct.ipynb` и сравнить с `xgb_direct.ipynb` на одинаковых строках, признаках, горизонтах и датах подбора. Обе модели прогнозируют исходный таргет. Оценивать прогноз из 10:30 по всем восьми горизонтам вместе и по каждому отдельно. Основание для проверки — в [отчёте по стекингу](stacking_report.md) отдельный лес получил 0,330295 на val и 0,344543 на test по суммарной метрике.

- [ ] **2. Прогноз остатков после удаления тренда и сезонности.** Для каждого маршрута оценить тренд по недавней истории и сезонность по средним отклонениям от тренда для получасового слота и дня недели. Для каждого исторического старта строить прогноз обеих компонент на восемь горизонтов только по наблюдениям, доступным к моменту старта. Обучить лес и бустинг на цели `y − прогноз тренда − прогноз сезонности`. При оценке прибавить обе компоненты к прогнозу остатка и считать метрику в исходном масштабе. Длину окна тренда подобрать до test. Сравнить с прямой версией каждой модели, с прогнозом одних компонент и с существующим вариантом поправки к `profile28`.

- [ ] **3. Представление `route_id` в случайном лесе.** Контроль — лес из эксперимента 1. В текущем ноутбуке маршрут уже представлен десятью двоичными признаками. По очереди заменить их одним целочисленным кодом (label encoding), one-hot, сглаженным средним таргета по маршруту (target encoding) или набором статистик маршрута без идентификатора (среднее, медиана, доля нулей). Для кодов использовать справочник train. Для средних и статистик брать только факты, известные к старту прогноза, в том числе при построении обучающих строк. Для нового маршрута использовать общий профиль по доступной истории. Сохранить параметры леса, остальные признаки и строки из эксперимента 1, чтобы измерить эффект именно замены представления.

Обучение запускает пользователь в Kaggle. Для всех трёх экспериментов разделить историю по времени, выбрать настройки на отдельном периоде до локального test и зафиксировать их перед оценкой. После обучения каждого зафиксированного варианта вывести таблицу для train и test с WAPE, модулем Relative Bias и их суммой. Перед сборкой сабмита переобучить все входящие в него модели на всей доступной размеченной истории. В итоговом отчёте явно указать, что независимая оценка test получена до этого переобучения. При повторном использовании уже просмотренных дат отметить это ограничение.

## Дополнительный эксперимент с локальными моделями

- [ ] Обучить отдельную модель для каждой пары маршрут–горизонт (1000 маршрутов × 8 горизонтов = 8000 моделей). В прямом варианте и в варианте на остатках использовать каждый доступный получасовой старт в течение суток. Для каждой обучающей строки признаки доступны на момент старта, а метка горизонта лежит в обучающем периоде. За 82 календарных дня до локального test получается до 82 × 48 = 3936 потенциальных стартов на маршрут до фильтрации по доступности истории и меток. При запуске вывести фактическое число обучающих строк по горизонтам. Подбор и локальный test оценивать по прогнозам из 10:30. Первый кандидат — Ridge с небольшим набором лагов и календарных признаков. Сравнить с восемью общими Ridge на тех же строках и признаках, сохранив идентификатор маршрута в общей модели. Подбирать регуляризацию совместно для маршрутов одного горизонта по конкурсной метрике на периоде подбора. Если прямой локальный прогноз уступает общей модели на подборе, проверить те же 8000 моделей на остатках после вычитания тренда и сезонности по протоколу эксперимента 2. Включить в сравнение прогноз тренда и сезонности без поправки. Вариант выбрать до просмотра локального test, применить общий протокол оценки и переобучения.

## Идеи для оценки пользователем, 8 ноября

Обсуждение, реализация не согласована. Проверки корреляций выполнены на истории до 4 октября, без обучения моделей. Каждый ряд делился на собственное среднее, затем корреляции считались по объединённым наблюдениям.

- Масштабированный MAE на всех восьми горизонтах как исправление текущего контроля. Дополнительно проверить фактический leaf_estimation_method в Kaggle и поддержку Exact установленной версией. Пока scaled реализован только для h=2.
- Прогноз поправки к сезонному уровню. Базовый прогноз строить отдельно для каждого исторического старта только из прошлого.
- Цепочки обработки: лаги каждого статуса, изменения и отклонения от обычного уровня маршрута/слота. status_3 имеет корреляцию с будущим нормализованным таргетом около 0,418 на h=1 и 0,009 на h=4; status_2 — 0,251 на h=2. Это описательные связи, не доказательство выигрыша.
- Динамическая общая нагрузка: агрегаты таргета и статусов по маршрутам до cutoff, их отклонения от обычного уровня. Опционально отдельный прогноз общего объёма и проверяемое согласование индивидуальных прогнозов с суммой.
- Длина окна и вес недавней истории: 14/28/56 дней против всей истории. Проверка будущих стартов только из 10:30, с одинаковыми датами сравнения.
- Профили соседних исторических слотов: t ± 30/60 минут вчера/неделю назад, диапазоны пиков, гармоники суточного профиля. Будущие слоты текущего дня недоступны.
- Режим смеси по горизонту и широким группам маршрутов с разной долей нулей и вариативностью. Общий вес как контроль, веса групп стягивать к нему.
- Сравнение MAE с RMSE либо Quantile на небольшом диапазоне alpha выше 0,5, подбор по полной конкурсной метрике. MAE оценивает медиану, штраф за общий объём может предпочесть другой баланс. Дополнительный вес крупных маршрутов при MAE без нормализации не вводить автоматически.

Проверка каждой идеи на нескольких последовательных временных окнах. Уже просмотренные последние 14 дат больше не считать нетронутым тестом для новых решений.
