# Ridge для каждой пары маршрут × горизонт

Ноутбук: `ridge_by_route_horizon.ipynb`. Он автономный: читает исходные parquet, строит признаки, подбирает параметры, оценивает модели, переобучает их и собирает submission. Версия v2 использует пакетные GPU-вычисления через CuPy и параллельную подготовку признаков на CPU. Запуск обучения выполняет пользователь в Kaggle или локальном Jupyter. Код не содержит assert, комментариев и докстрингов.

## Протокол

- 1000 маршрутов × 8 горизонтов: 8000 финальных sklearn Ridge.
- Train: все получасовые старты с временем целевой метки строго до начала val.
- Val: 4–17 октября 2025, только старты 10:30.
- Test: 18–31 октября 2025, только старты 10:30.
- Границы вычисляются из последних 28 полных дней истории, а не зашиты в код. Указанные даты соответствуют истории, заканчивающейся 1 ноября 2025 в 10:30.
- Отдельная Optuna study для каждой пары: 30 trials, alpha от 1e-4 до 1e6, логарифмическая шкала, intercept включён.
- Цель Optuna: WAPE + |Relative Bias| пары на всём val. При нулевой сумме факта — MAE с явной отметкой; конкурсная метрика остаётся неопределённой.
- После фиксации всех настроек — обучение на всех получасовых стартах train + val с метками до test. Затем независимая оценка на test.
- После сохранения оценки — новое обучение на всей размеченной истории, включая все допустимые старты дней val/test и последнего неполного дня.
- Все прогнозы обрезаются снизу нулём. Калибровки, смешивания и логарифмирования цели нет.

Независимая оценка test получена до переобучения на всей размеченной истории. Даты test уже использовались в других экспериментах проекта и не являются новым слепым holdout.

## Признаки и преобразования

Формулы перенесены из актуального `feature_engineering.ipynb`: цель и статусы, скользящие средние, изменения, комбинации статусов, исторические и сезонные окна ±2 часа, форма сезонных профилей, сетевые суммы, корреляционные лаги исходных и очищенных от сезонности рядов. Для календаря используются только четыре признака: sin/cos дня недели и получаса суток. Служебные идентификаторы и временные метки, profile28 и overlap не входят в модель.

Признаки используют факты до собственного cutoff. Словарь корреляционных лагов строится заново на обучающей части каждого этапа. Медианы пропусков, исключение постоянных колонок и стандартизация также обучаются только на соответствующей обучающей части. При полном отсутствии изменяющихся колонок сохраняется одна постоянная колонка для технической возможности fit; Ridge прогнозирует свободный член.

Итоговые метрики агрегируются из суммарных ошибок, а не усредняются по 8000 парам. Train и train + val оцениваются на всех стартах, test — только в 10:30. Сохранены также метрики по парам, горизонтам и дням test.

## Запуск и ресурсы

В начале ноутбука задаются пути к parquet, OUTPUT_ROOT и настройки исполнения. На Kaggle входы автоматически ищутся в `/kaggle/input`, выходы пишутся в `/kaggle/working`. Локально ожидается папка `data` в текущей рабочей директории Jupyter. При неоднозначном поиске входов нужно задать пути явно.

| Настройка | По умолчанию | Назначение |
|---|---|---|
| DEVICE | `cuda` | GPU обязателен; `cpu` выбирает NumPy; `auto` разрешает явный переход на CPU при недоступной CUDA |
| MAX_BATCH_SIZE | 16 | Максимальное число независимых моделей в пакете |
| FEATURE_WORKERS | 2 | CPU-потоки для подготовки признаков с отдельным состоянием маршрута |
| BLAS_THREADS | 1 | Число BLAS-потоков для CPU-операций |
| HOST_MEMORY_FRACTION | 0.25 | Доля доступной RAM для предварительной оценки размера пакета |
| GPU_MEMORY_FRACTION | 0.60 | Доля свободной VRAM для предварительной оценки размера пакета |
| CPU_REFERENCE_PAIRS | 2 | Число пар каждого этапа для сверки с обычным sklearn Ridge |

Для CUDA 12 установите `cupy-cuda12x`, для CUDA 13 — `cupy-cuda13x`, затем перезапустите kernel. Не устанавливайте одновременно несколько сборок CuPy. На Kaggle включите NVIDIA GPU; локально нужен совместимый драйвер. При запуске выводятся имя устройства и свободная VRAM; небольшая проверка пакетных eigh/solve выполняется до загрузки данных. В режиме `cuda` ошибка CUDA останавливает запуск, а не незаметно переключает вычисления на CPU.

GPU вычисляет XᵀX, разложения, решения Ridge, прогнозы и метрики для пакета пар. Optuna остаётся на CPU: по одному ask для каждой активной study, общая оценка предложений на GPU, затем отдельный tell в каждую study. Каждая модель сохраняет свой sampler, seed и историю. При переборе alpha разложение одной матрицы переиспользуется. Оценочное и финальное обучение также выполняются пакетно на выбранном устройстве.

Матрицы разных размеров дополняются нулями; добавленные строки не участвуют в метриках. Размер пакета ограничивается оценкой свободной RAM/VRAM. При CUDA OutOfMemoryError пакет повторяется половинами вплоть до одной модели. Эта оценка не гарантирует отсутствие нехватки памяти; если даже одна модель не помещается, запуск останавливается с объяснением. В память не загружается общая матрица признаков всех маршрутов. Подготовка признаков параллельна внутри пакета; она не перекрывается по времени с вычислением предыдущего пакета.

Матричная арифметика — float64. Это сохраняет устойчивость при малых alpha и коррелированных признаках, но может ограничивать ускорение на потребительской GPU. Коэффициенты переносятся в обычную sklearn Ridge без повторного CPU fit; CuPy не требуется при загрузке этих файлов для инференса. Для всех решений проверяется невязка, для выбранных параметров — совпадение спектрального и прямого решения. Первые две пары каждого этапа сверяются с CPU sklearn Ridge. Каждый финальный файл загружается обратно для сверки прогноза.

Численное ускорение на RTX 4060 не измерено. В `reports/timings_search.csv`, `timings_evaluation.csv`, `timings_full.csv` записываются время подготовки, вычислений вместе с сохранением и ETA этапа. Таймер учитывает синхронизацию CUDA. Архивация добавляет время. Время всего этапа зависит также от CPU-признаков, Optuna и диска, поэтому перенос матричных операций на GPU сам по себе не гарантирует ускорения.

## Результаты и продолжение

- `models/ridges/h1…h8/route_XXXX.joblib`: ровно 8000 финальных моделей при полном запуске. Внутри каждой — Ridge, преобразования, признаки, словарь лагов и метаданные.
- `artifacts/ridge_by_route_horizon/studies`: Optuna checkpoints каждые пять trials и по завершении пары, вместе с состоянием sampler.
- `params`, `trials`: выбранные параметры и метрики train/val каждой попытки.
- `evaluation`: независимые test-прогнозы и метрики каждой пары до полного refit.
- `full`: полные in-sample метрики, прогнозы конкурсного test, коэффициенты.
- `reports`: сопоставление индексов маршрутам, границы, сводные метрики, перечень всех моделей.
- `submission.csv`: id и y_pred в исходном порядке.
- `ridge_by_route_horizon.zip`: модели, результаты и checkpoints для скачивания.

Повторный запуск с теми же настройками и входами продолжает сохранённый расчёт. Полные хеши входных файлов, backend и версии библиотек защищают от случайного смешивания запусков. Checkpoint содержит завершённые trials и состояние sampler; после прерывания может потребоваться повторить до четырёх последних попыток каждой активной study. MAX_BATCH_SIZE, FEATURE_WORKERS и доли памяти можно менять при продолжении. При изменении параметров эксперимента, смене CPU/CUDA или переходе с прежнего v1 используйте новые RUN_ROOT и MODEL_ROOT: старые результаты не перезаписываются. Одновременно два процесса в один каталог запускать нельзя. В новой Kaggle-сессии необходимо восстановить обе папки из сохранённых выходов в доступное для записи место. До удаления текущей сессии сохраните её выходные файлы.

Загрузку файла и применение к уже подготовленным признакам показывает раздел финального обучения ноутбука. Для построения новых лаговых признаков дополнительно нужна исходная история; модельный файл не содержит все исходные временные ряды.

## Проверки

`scripts/check_route_ridge_gpu.py` выполняет цикл на синтетических данных без чтения пользовательских parquet. По умолчанию проверяется CPU-режим того же пакетного алгоритма. Для проверки реальной CUDA используйте `python scripts/check_route_ridge_gpu.py --device cuda` в окружении с CuPy и NVIDIA GPU. Это отдельная проверка, а не обучение 8000 моделей на реальной истории.

Официальные справки: [sklearn Ridge](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html), [Optuna ask/tell](https://optuna.readthedocs.io/en/stable/reference/generated/optuna.study.Study.html), [CuPy eigh для пакета матриц](https://docs.cupy.dev/en/stable/reference/generated/cupy.linalg.eigh.html), [CuPy solve](https://docs.cupy.dev/en/stable/reference/generated/cupy.linalg.solve.html), [установка CuPy](https://docs.cupy.dev/en/stable/install.html).
