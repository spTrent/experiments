# Прогноз отправлений по маршрутам RWB

В 10:30 нужно предсказать `target_1h` для 1 000 маршрутов на восемь получасовых горизонтов, с 11:00 до 14:30. Сабмит содержит 8 000 строк с колонками `id,y_pred`.

**Лучший результат команды на закрытом тесте составляет 0,326.** Это запуск Session6. Его модели, прогнозы и код находятся в [best](best/), отправленный файл сохранён как [submission_session6.csv](best/submission_session6.csv).

## Как устроено лучшее решение

Session6 объединяет два прогноза.

Первый получен решением с результатом 0,328. Оно использует CatBoost, сезонный профиль и модели поправок по историческим ошибкам. Его сумма по маршрутам задаёт объём каждого горизонта.

Второй прогноз строят восемь моделей LightGBM. Они обучаются на нормированном уровне маршрута с пятью утренними стартами. Прогноз LightGBM приводится к суммарному объёму первого компонента. Затем два прогноза смешиваются с весом LightGBM **0,4997259**, выбранным на 11-17 октября 2025 года.

Такое смешивание меняет распределение между маршрутами, сохраняя суммарный объём каждого горизонта. На локальном test WAPE снизилась с 0,320090 до 0,317827, а модуль общего смещения сохранился.

| Оценка | Решение 0,328 | Session6 |
|---|---:|---:|
| WAPE | 0,320090 | 0,317827 |
| Модуль Relative Bias | 0,001364 | 0,001364 |
| WAPE + модуль Relative Bias | 0,321454 | **0,319190** |
| Средняя дневная метрика | 0,338301 | 0,336039 |

Локальная проверка охватывает 18-31 октября 2025 года, 112 000 прогнозов из 10:30. Результат 0,326 на закрытом тесте сообщён командой. В Session6 исходные модели загружались из файлов, повторное обучение не выполнялось. Это отмечено в манифесте как `source_models_refitted=false`. [Конфигурация](best/bundle/config.json), [метрики](best/bundle/metrics.csv), [манифест](best/bundle/manifest.json).

## Данные и метрика

История содержит 4 630 000 строк с 28 июля по 1 ноября 2025 года, 10:30. Для каждой строки известны маршрут, время, цель `target_1h` и шесть статусов. Конкурсный прогноз строится на 1 ноября. Файлы лежат в [data](data/), описание задачи и правила в [docs/competition](docs/competition/).

Метрика соревнования равна **WAPE + |Relative Bias|**. WAPE измеряет сумму абсолютных ошибок относительно общего фактического объёма. Relative Bias измеряет суммарную ошибку со знаком относительно того же объёма. Меньше лучше.

Дополнительно считаем среднюю дневную метрику. В ней каждый день имеет одинаковый вес. При расчёте по всему периоду положительные и отрицательные дневные смещения могут компенсироваться, поэтому две оценки иногда по-разному ранжируют модели.

## Обучение и проверка

Основное разбиение проекта задано по времени.

| Период | Даты 2025 года | Использование |
|---|---|---|
| Train | 28 июля - 3 октября | Обучение моделей. |
| Подбор | 4-17 октября | Выбор параметров, смеси и калибровки. |
| Локальный test | 18-31 октября | Проверка выбранной конфигурации. |

В отдельных экспериментах используются более ранние недельные окна. В Session6 вес смеси выбран на 11-17 октября. Границы конкретного запуска указаны в его ноутбуке.

1. Для каждого горизонта формируем метку и признаки, известные к старту прогноза. Используем лаги цели и статусов, скользящие средние, календарь, исторические слоты и сезонные профили.
2. Подбираем параметры на датах до test. Пропуски, масштабы, кластеры и корреляционные лаги оцениваем на train текущего окна.
3. Для ансамблей строим OOF-прогнозы, каждый после обучения на предыдущих датах. По ним выбираем смесь и поправки.
4. Фиксируем настройки и выводим train/test с WAPE, модулем Relative Bias и их суммой.
5. Перед новым сабмитом переобучаем модели на всей доступной размеченной истории с выбранным правилом окна обучения. Проверяем порядок `id`, полноту и значения итогового CSV.

**Независимая оценка test получена до финального переобучения.** Это относится к сохранённым оценочным моделям. Октябрьский test уже использовался в нескольких экспериментах, поэтому последующие решения проверяем также на последовательных временных окнах. Для Session6 сохранён комплект восстановления готового прогноза, отдельный полный refit в нём не выполнялся.

Описание признаков и подробные правила экспериментов находятся в [docs/feature_engineering.md](docs/feature_engineering.md) и [docs/model_experiments.md](docs/model_experiments.md).

| Окно истории и пики | В эксперименте 03 выбран `recent75 + peaks + MAE`. Дневная метрика снизилась с 0,338366 до 0,338001, эффект различался по неделям. [Отчёт](docs/03_windows_features_report.md) |

## Следующие проверки

1. Обучить поправки очищенных моделей на исходной цели. Проверить, связано ли ухудшение bias с очисткой обучающих ответов.
2. Подобрать поправки отдельно по горизонтам с регуляризацией к общему коэффициенту. В Session6 ранние и поздние горизонты имеют разные направления смещения.
3. Сравнить единый вес LightGBM с несколькими весами по группам горизонтов при фиксированном объёме.
4. Обучить LightGBM напрямую предсказывать доли маршрутов в объёме горизонта.
5. Сравнить очистку только входов с очисткой входов и цели. Отдельно проверить нули и крупные объёмы.

Выбор проводим на временных окнах до test, затем проверяем перенос на следующий период. План с условиями каждого опыта приведён в [docs/next_five_experiments_0326.md](docs/next_five_experiments_0326.md).

## Запуск

Для восстановления лучшего сабмита откройте [best/session6.ipynb](best/session6.ipynb), выберите окружение с зависимостями из `best/bundle/requirements-reproduce.txt` и выполните ячейки по порядку. Достаточно CPU.

Обучения выполняются в Kaggle. Импортируйте нужный ноутбук, подключите исходные parquet, включите GPU и выполните **Save & Run All**. В первой ячейке указаны пути, параметры и бюджет. Для `stepa330` итоговый файл называется `submission_team_scaled_experiments.csv`.

Порядок запуска распределённого стекинга описан в [инструкции](stacking/STACKING_ASSEMBLY_GUIDE.md). При локальной работе относительные пути `data/` и `artifacts/` отсчитываются от корня репозитория. Генераторы в `scripts` перезаписывают одноимённые ноутбуки вместе с сохранёнными выводами.
