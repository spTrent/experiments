# Пять следующих проверок для решения 0,326

Основание: `best/raw-vs-clean.ipynb`, архив 0,326, полный Output сравнения median6/seasonal_mad и повторный анализ построчных прогнозов. Это план проверяемых гипотез, не обещание улучшения. Модели при подготовке плана не обучались.

## Почему именно эти пять

На уже изученном test 18–31 октября raw имеет WAPE 0,317827, общий bias −0,1364% и сумму 0,319190. Средний модуль дневного bias — 1,8118%, максимальный — 4,8158%. Поэтому почти нулевой общий bias не означает, что объём каждого дня/горизонта предсказан точно.

Есть конкретное расхождение в очищенных ветках: модели поправки и causal_offsets используют `fit_y`, то есть очищенную цель, при оценке по исходной `y`. В fit-периоде поправок 4–17 октября median6 убирает 0,0663% суммарной цели, seasonal_mad — 0,0800%. Дополнительный модуль test-bias этих веток относительно raw — около 0,0883 и 0,0857 процентного пункта. Масштабы близки, но это не доказывает причинность: модели и адаптивные поправки нелинейны, а периоды различаются.

По горизонтам bias raw: h1 −1,01%, h2 −1,55%, h3 −1,99%, h4 −1,27%, h5 +2,19%, h6 +3,32%, h7 +0,61%, h8 −1,02%. Общая поправка не различает эти направления.

В форме распределения между маршрутами тоже есть большой объём ошибки. При фиксированных предсказанных суммах для каждой пары день/горизонт нижняя граница WAPE равна sum|sum_routes(pred−y)|/sum(y) = 0,034375 против фактических 0,317827. Это вычисленная по истинным test-ответам недоступная при прогнозировании граница, а не достижимый результат или обещанный потенциал улучшения. Она обосновывает проверку распределения, а не только общего объёма.

Источники чисел: `artifacts/next_five_steps/evidence.json`, `baseline_horizon_diagnostics.csv`, `calibration_label_volume_shift.csv`. Исходные метрики воспроизводятся с float64 до 1e-12.

## 1. Оставить очищенные базы, но поправки обучать на исходных ответах

**Изменение:** не трогать базовые CatBoost/LightGBM, признаки, параметры и вес смеси. Поменять только целевые значения слоя поправок и оценки смещения:

- остаточная цель в finish_pipeline: `frame.y - frame.raw_blend` вместо `frame.fit_y - frame.raw_blend`;
- initial offset: среднее исходного y минус unshifted на допустимом fit-периоде;
- история ошибок causal_offsets: исходный y минус unshifted, с тем же ограничением доступности во времени.

**Сравнение:** прежняя clean-ветка против той же ветки с raw-y поправками. Обе известные очистки можно проверить на этих же сохранённых базовых весах. Это не новое масштабное обучение баз: надо восстановить OOS-таблицу исходных входов поправки и обучить только небольшие модели остатка. Не подменять их in-sample остатками после обучения на всех датах.

**Почему первым:** напрямую согласует калибровку с измеряемой величиной и проверяет найденную причину дополнительного недопрогноза. Очистка входов сохраняется полностью.

**Критерий:** на более ранних последовательных окнах уменьшается модуль дневного/общего bias без значимого ухудшения WAPE; улучшение суммы не держится на одном дне. После фиксации — test по исходным ответам.

**Риск:** удалённые пики могут быть реальными ошибками измерений; возвращение их в цель может не помочь. Само совпадение масштаба потери объёма и сдвига bias не заменяет эксперимент.

## 2. Проверить причинную поправку объёма по горизонту с усадкой к общей

**Изменение:** текущая causal_offsets добавляет один общий offset, оценённый по всем горизонтам/маршрутам. Сравнить с поправками по горизонту: сглаженные отношения сумм или аддитивные остатки, с регуляризацией к общей поправке. Первым контролем выбрать один вид поправки, чтобы не смешивать восемь множителей, восемь offsets и несколько режимов одновременно.

**Причинная схема:** для каждого cutoff использовать только метки, уже известные с прежним запасом четыре часа. Короткую историю каждого горизонта стягивать к общей оценке; силу стягивания определять по числу доступных дат, а не по числу маршрутных строк. 1 000 маршрутов дня не дают 1 000 независимых оценок дневного объёма.

**Сравнение:** global-EWMA из контроля против horizon-EWMA с тем же полупериодом. Цели обеих поправок исходные. Нельзя просто вычислить восемь коэффициентов по показанному test и представить это как улучшение.

**Почему:** по h3 ошибка объёма отрицательна примерно на 1,99%, по h6 положительна на 3,32%, хотя общая сумма почти сбалансирована. Новое здесь — раздельная динамика горизонтов с усадкой; сама скользящая калибровка уже существует и ранее давала неоднозначные результаты.

**Критерий:** средняя дневная WAPE + |Bias| по всем восьми горизонтам улучшается на нескольких окнах; проверить также pooled, WAPE и h1 отдельно. Не выбирать метод по среднему арифметическому score горизонтов: оно не равно конкурсной метрике полного прогноза.

**Стоимость:** низкая по сравнению с переобучением баз. **Риск:** небольшой pre-test период, нестабильные коэффициенты и перенос калибровки после refit.

## 3. Заменить один вес формы несколькими сильно регуляризованными весами

**Изменение:** вместо одного shape_weight=0,4997259 для всех горизонтов проверить небольшое число весов смеси двух существующих компонентов. Например, три группы h1 / h2–h4 / h5–h8, со стягиванием к общему весу и ограничением [0,1]. Эти группы — новая гипотеза после анализа, не независимое подтверждение с test.

**Что сохранить:** прогноз объёма и сумма каждого горизонта должны остаться прежними. Смешивать распределения по маршрутам, нормированные к одному объёму. Тогда опыт проверяет именно форму, а не скрытую смену общего bias.

**Почему:** один общий вес подразумевает одинаковую относительную полезность CatBoost/LightGBM на h1 и h8. В текущем решении ветки имеют разную структуру признаков и обучения, а качество меняется по горизонту. Уже сам переход к смеси форм улучшил архивную локальную WAPE с 0,320090 до 0,317827; это не доказывает пользу дополнительных весов, но даёт основание проверить их.

**Выбор:** только на сопоставимых OOF-прогнозах до test с оценкой на следующем временном блоке. Архивный raw из best содержит только итоговый test и не заменяет такой OOF. Сравнить с существующим общим весом и с простыми контрольными весами; не начинать с отдельного веса на каждый маршрут.

**Критерий:** WAPE улучшается при неизменных суммах, эффект повторяется на нескольких блоках. На короткой истории оценённые веса могут переобучаться; простые смеси часто устойчивее сложных, что подробно обсуждается авторами FPP. [Forecast combinations](https://otexts.com/fpp3/practical.html#forecast-combinations).

**Стоимость:** низкая при готовых OOF, иначе потребуется их восстановление. **Риск:** переобучение на 7–14 датах и выбор групп по уже изученному test.

## 4. Обучить LightGBM непосредственно на маршрутные доли

**Изменение:** нынешний LightGBM прогнозирует target/уровень маршрута, после чего его прогнозы нормируются к сумме другой модели. Сравнить с целью `share = y_route / sum_routes(y)` для каждой пары cutoff/horizon. Для численной устойчивости можно масштабировать доли константой; не менять одновременно остальные признаки и параметры.

**Обучение:** знаменатель из будущих фактов разрешён только как часть обучающей цели, не как входной признак. Для соответствия ошибке в исходном объёме пример взвешивается суммарным фактом своей пары cutoff/horizon. Полную панель маршрутов каждой пары надо сохранять. Прогнозы долей ограничиваются снизу нулём и нормируются до суммы 1; нулевую сумму обрабатывать заранее заданным fallback из train.

**Прогноз:** итог = зафиксированный прогноз объёма горизонта × предсказанные доли. Будущая истинная сумма не используется. Сравнить WAPE при одинаковом объёме с текущим LightGBM-распределением; затем на pre-test OOF решить, заменять форму или смешивать небольшой долей.

**Почему:** это согласует обучающую задачу компонента с его фактической ролью в решении 0,326. Сейчас модель обучается нормированному абсолютному уровню, а используется как распределитель чужого объёма. Общая архитектура «агрегат + доли» известна в прогнозировании групп рядов, но конкретная обучаемая форма и её выигрыш для RWB остаются нашей гипотезой. [Grouped forecasting and reconciliation](https://otexts.com/fpp3/hierarchical-forecasting.html).

**Критерий:** уменьшается WAPE при точно одинаковых суммах каждого горизонта. **Стоимость:** новое обучение восьми LightGBM. **Риск:** зависимость от качества прогноза объёма; сырые и очищенные доли нельзя смешивать в цели без явного решения. Использовать исходные y для формирования долей.

## 5. Переобучить базовые модели: очистка только X, исходный y

**Изменение:** оставить выбранный причинный фильтр для исторических рядов и признаков, но базовые CatBoost и LightGBM обучать на `original_target`, а не на очищенном target. Для LightGBM сохранить преобразование масштаба и веса так, чтобы оценка проводилась в исходных единицах. Слой поправки тоже использует исходные ответы по шагу 1.

**Три сопоставимые ветки:** raw X/raw y; clean X/clean y из нынешнего опыта; clean X/raw y. Первая проверка — одна seasonal_mad-ветка, без нового перебора порогов. Нули по-прежнему сохраняются. Все версии исходных значений, из которых строятся лаги, должны быть доступны к собственному cutoff.

**Почему:** нынешняя очистка одновременно меняет входы, профили, обучающие ответы, модели поправки и онлайн-историю bias. По этому опыту нельзя понять, не было ли полезное исправление X компенсировано ухудшением Y. Шаг 1 проверяет только дешёвый слой поправок, этот шаг отдельно меняет обучение баз.

**Критерий:** на исходных ответах улучшаются WAPE/сумма относительно raw, а не только smoothness рядов. Отдельно смотреть нули и верхние 5% фактов: у нынешних очисток на верхнем хвосте улучшения не подтверждено.

**Стоимость:** самая высокая из пяти — новые CatBoost/LightGBM и OOF. **Риск:** безусловная очистка X всё ещё может уничтожать настоящий пик; сохранение y само по себе не решает плохой детектор. Разделение аномалий входов и меток подробно рассматривается в RobustTSF; перенос его результатов на наш бустинг требует своего контроля. [RobustTSF, ICLR 2024](https://arxiv.org/pdf/2402.02032).

## Общий протокол и порядок запуска

Практический порядок: 1 → 2 → 3; после дешёвых проверок — 4 и 5. Не складывать все изменения в одну модель до индивидуальных сравнений. Признаки и модели не дополнять по правилу «хуже на этом test — удалить»: этот период уже видел много экспериментов.

В текущем архиве raw не переобучался восстановленным тренером. Для строгого сравнения нужен один сопоставимый raw-контроль на тех же версиях библиотек и временных границах, с OOF до test. Архив 0,326 сохранять отдельным ориентиром. Это инфраструктура сравнения пяти гипотез, а не заявленное улучшение метрики.

Для подбора использовать последовательные блоки до итогового test, не случайные строки. Согласовать OOF: прогноз каждого блока базами из более ранних дат, поправки/веса — из предыдущего блока, итоговая оценка — на следующем. Выбранные параметры XGBoost/CatBoost/LightGBM не менять одновременно с экспериментом.

Сохранить последнее указание пользователя: после выбора по val можно обучить базы на train + val с целями строго до test и применить зафиксированную OOS-калибровку. Test в fit не включать; полного переобучения на всей истории и сабмитов в этом цикле не делать. Контроль должен пройти такой же refit, иначе изменение свежести данных смешается с эффектом кандидата. Перенос калибровки после refit проверить отдельно по выводу raw/calibrated.

После каждого обучения показывать train/test с WAPE, |Bias| и суммой; дополнительно signed Bias, среднюю дневную метрику, срезы по горизонтам. Указать, что оценка test получена без включения test в fit и до какого-либо полного переобучения. Нельзя объявить успех на leaderboard по одному локальному score.

## Что я бы сейчас не ставил первым

Ещё один большой стекинг; 1 000 независимых маршрутных множителей; новая тотальная очистка с меньшим порогом; подбор модели по pooled bias всего test. Из двух test-недель корреляция маршрутного bias всего 0,213, знак сохраняется у 55,6% маршрутов. Это описательная оценка, но она не даёт оснований начинать с высокоразмерной маршрутной калибровки. Новые веса и параметры должны определяться на более ранних блоках.

Выигрыши пяти предложений пока не измерены. Сильнее всего кодом и данными обоснован первый шаг; остальные — конкретные гипотезы с изолированным изменением, контролем и критерием принятия. Обучение выполняет пользователь в Kaggle.
