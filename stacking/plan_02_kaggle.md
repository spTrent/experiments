# Запуск согласованного стекинга в Kaggle

Для текущего расширенного пути с локально подобранными Ridge используйте [полную инструкцию по сборке](STACKING_ASSEMBLY_GUIDE.md): перенос между аккаунтами, 46 кандидатов, test и submission_tuned.csv.

Первый запуск: `PROFILE='five_starts'`, `OOF_WEEKS=(2,3,4)`, фиксированный `ROUTE_ALPHA=100`. Пять обучающих стартов 09:30–11:30 по всей истории train, без отсечения первых 25% дат и без подбора параметров баз. Полный перебор метамоделей сохранён: 14 конфигураций Weighted Average / CatBoost / GatingNetwork с маршрутной Ridge и без неё, затем четыре прежние поправки и 14 дополнительных калибровок лучшего исходного кандидата (32 кандидата всего). Новые калибровки: горизонт, группы маршрутов, иерархическая, сдвиг, аффинная, нелинейная, ситуационная, каждая с силой 50%/100%. Профиль `recent75` также доступен, но его результаты изолированы и не смешиваются с пятистартовым запуском.

## Порядок запусков

1. На четырёх аккаунтах подключить исходные train/test parquet, включить T4 x2. Выполнить `MODE='oof'`, `ROLE='worker'` во всех частях.
2. В части 1 подключить четыре output, выполнить `MODE='assemble'`. Сборщик проверит 168000 OOF-строк, сравнит метамодели на двух временных проверках и сохранит winner.json.
3. Во всех частях подключить winner и свои сохранённые выходы, выполнить `MODE='evaluate'`, `ROLE='worker'`.
4. В части 1 подключить четыре результата оценки и весь output assemble (включая историю калибровки), выполнить `MODE='evaluate'`, `ROLE='collect'`.
5. Во всех частях подключить отчёт оценки, winner и сохранённые выходы, выполнить `MODE='submit'`, `ROLE='worker'`: дополнительная неделя и финальное обучение баз.
6. В части 1 подключить четыре результата submit и выходы assemble/evaluate, выполнить `MODE='submit'`, `ROLE='collect'`. Итог — `submission.csv`.

Сборку выполняет только часть 1. Рабочие части независимы внутри этапа; последующие этапы зависят от завершения предыдущих. Внутри одного worker обучение последовательно.

## GPU и продолжение

RF использует cuML, XGBoost — CUDA, CatBoost — GPU, глобальная и маршрутные Ridge — CuPy. LightGBM проверяет CUDA и OpenCL и при недоступности использует CPU с сообщением. Две T4 не означают автоматического распределения двух горизонтов по картам.

`SESSION_HOURS=11` останавливает рабочий процесс до лимита сессии Kaggle. Завершённые fit сохраняют прогнозы и метрики, маршрутные Ridge — пакеты. Подключите весь сохранённый output к следующей сессии с теми же настройками. Незавершённый fit и временные таблицы признаков будут рассчитаны заново. Старые выходы с другим CODE_ID не переиспользуются автоматически.

Для короткого запуска можно указать `OOF_WEEKS=(2,)`, затем подключить результат и вернуть `(2,3,4)`. Assemble требует все три недели. Для всех четырёх частей нужны одинаковые версия кода, исходные данные и alpha.

## Замер и воспроизводимость

`rf_recent75_benchmark.ipynb` — отдельный диагностический ноутбук: по умолчанию h1, direct/residual, train до 18 октября, последние 75% дат. Он отдельно измеряет признаки, fit и predict. Его результаты не являются checkpoint для stacking.

Фактическое время на T4 пока не измерено. Сокращение количества fit не равно пропорциональному ускорению: глобальные исторические расчёты остаются, но таблицы признаков горизонта в five_starts строятся только для пяти стартов вместо 48. Рабочие ноутбуки сохраняют времена этапов и вычисляют ETA по завершённым фолдам.

Четыре ноутбука генерируются `scripts/build_stacking_notebooks.py`. При отсутствии исходных каталогов model_params используется точный снимок 80 конфигураций в `scripts/stacking/model_params.json`, извлечённый из прежних автономных ноутбуков. Изменение этого протокола не меняет параметры моделей.
